### 一、剑体玩法重定（2.22.x，服主拍板）

### 二、耐久账补全（2.23）

- **护甲虚拟耐久开始扣账**：锻造品本体 unbreakable、原版条冻结，此前只有武器砍怪扣账，护甲挨打数值（如 4500）永不动。现在护甲真正吃到减伤的伤害会掉账（节流窗口 `armor-wear-throttle-ms`，默认 500ms），崩刃同武器规则：词条套装停算、`/zhujian repair` 手持研磨。

- **耐久显示档宽可配**：`durability-lore-step`（默认 5%，0 = 每刀实时刷新）。

## 十四·补五、v2.23.5：「内置耐久不掉」的真因与 Tab 补全收口

服主两条反馈：①「内置耐久又不掉了，几千点的那个，是不是加了无法破坏」；
②「新加了几条同步全服数据的指令我忘了叫啥，把没补全的都给我补上」。

### 一、内置耐久其实一直在掉，是「数字」没掉

先给结论，都有真机数据（`tools/guitest/durability-check.js`，测试服 2.23.5）：

```
start dur=3900 | 耐久 ▸3900/3900
  hit1 PDC=3897 | 耐久 ▸3899/3900     ← 数字停着
  hit3 PDC=3893 | 耐久 ▸3894/3900     ← 每 5 点跳一次（修好之后）
  hit10 PDC=3879 | 耐久 ▸3879/3900
```

- **PDC 那条账从来没停过**：每刀稳定 -1（连击时穿甲扫到旁边会多扣一刀）。
- `unbreakable: true` 是 **2.10.3 起就写进去的设计**，只封原版耐久条（不然原版条见底整把剑直接碎，
  Lore 上还显示 80%）。它**不影响**插件自己的耐久账，这点自检里也钉着。
- 真正的问题是 **Lore 上的数字不刷新**：档宽原来只有百分比，`5% × 3900 = 195 点`，
  也就是说**砍 195 刀**那个数字才动一次。玩家砍完一只怪，看到的还是满耐久 —— 这就是「不掉」。

修法（`ItemFactory.durabilityBandWidth`）：百分比之外再夹一层绝对上限
`settings.durability-lore-max-points`（默认 5 点）。几千点的剑每 5 刀跳一次数字，
小件仍按 5% 走，Lore 重写频率仍是 1/5 刀，不碰热路径性能。
老盘由迁移 step29 / step15 自动补键，`/zhujian config check` 225 项全齐。

自检新增两条钉子：

| 断言 | 想防的事 |
| --- | --- |
| 大耐久品的显示档宽必须 ≤ 5 点 | 又有人把档宽改回纯百分比，数字重新「冻住」 |
| 掉 1 个档宽，Lore 数字必须变、且 PDC 跟上 | 只改 Lore 不改 PDC（或反过来）的半截修法 |

### 二、Tab 补全：从「手抄一份」改成「分派表的镜像」

以前补全表是一张手写死表，`onCommand` 加了 `case` 没人记得往补全里补 ——
`fixattrs`（收敛全服存量物品那条）就这么在代码里躲了两个版本，服主只能靠记。

现在：

1. `ForgingCommand.SUBCOMMANDS` 是**分派 switch 的镜像**（每条 case 的完整别名组，主名在第一位），
   首层补全由它展开 —— 加分派只改这一处。
2. 每条子命令按「现在在补第几段」给候选，一直给到最后一层（玩家名 / 剑胚 id / 谱号 /
   拍卖单号 / 档宽数字 … 全部现取）。
3. 后端服务（行会 / 师徒 / 出师 / 订单 / 剑灵 / 剑冢 / 秘境 / 拍卖）的子命令一并覆盖，
   别名与中文写法都给（`taozhuang`、`qiandao`、`gao`… 玩家敲什么都不至于按 Tab 没反应）。

自检里那张 `expects` 表就是命令语法本身，另外加了一条**给以后留的钉子**：

> 除「叶子命令」白名单（`codex` / `shop` / `signin` … 这些确实没有下一层）外，
> **每条子命令的第二层都必须有候选**。新加 case 忘了配补全，自检立刻红。

真机结果：

```
自检完成：共 484 项，通过 484，失败 0        （上一版 483 项 / 483 通过）
```

### 缺陷 3：老物品强化「白做」

这是最值钱的一条。`baseOf` 在物品**没有基础属性快照**时，会拿当前 modifier 除以倍率反推基础值：

```
base = modifier ÷ mult_new       ← 求 base
modifier = base × mult_new       ← 写回去
```

一除一乘**正好抵消**。2.4 之前铸出来的武器没有 `BASE_ATK` 快照，于是第一次强化：

```
1.12 → 1.12      （材料扣了，剑币扣了，数字一动不动）
```

修法是改顺序：**在改等级之前**用旧倍率把当前 modifier 锁成快照。

```java
int target = Math.max(0, Math.min(cap, level));
seedSnapshot(item, levelOf(item));   // ← 必须在 writeLevel 之前
writeLevel(item, target, cap);
apply(item);
```

顺序反了就没用 —— 这正是加上注释锁住的原因。

### 顺带发现：0.6%/级 在 2 位小数下会被舍掉

修完顺序，第二次强化还是不涨：

```
第二次强化又没涨：1.13 → 1.13
```

根因不是顺序，是**精度**。默认 `bonus-per-level: 0.006`，对基础攻击 1.12 的剑，一级只加 `0.0067` —— `Math.round(v*100)/100` 直接抹平。

所以内部累加改成 4 位小数（`roundStat`），显示仍然是 2 位：

| 用途 | 精度 | 理由 |
| --- | --- | --- |
| PDC 快照 / modifier 数值 | 4 位 | 每级增量必须能累加，否则连锤十级原地踏步 |
| Lore / 面板文字 | 2 位 | 玩家不需要看 1.1267 |

`ItemFactory` 也必须同精度 —— 创建时写 2 位、强化时按 4 位重算，第一次 `apply()` 会把 1.71 校正成 1.708，玩家看到的是「我什么都没做，属性变了」。

### 缺陷 5：每日悬赏重启变空

`bounty-data.yml` 里只有 `day: 20768`，**没有存悬赏列表**。而 `current()` 的换日条件是：

```java
if (today != day) { ... current = roll(today); ... }   // 原来
```

重启后 `day` 等于今天 → 不重掷 → `current` 是空的内存列表 → 玩家看到「今日悬赏：无」，一直空到第二天零点。

两处一起修：

```java
// ① 日期对但列表是空的，也必须重掷（重掷是确定性的，种子=日期，内容不会变）
if (today != day || current.isEmpty()) { ... }
// ② 列表本身也落盘
yml.set("list", rows);   // "quality,level,stage,reward"
```

### 一、判据：什么才算「特殊附魔」

写代码前先定三条红线，避免又滑回换皮：

1. **原版有没有这个机制？** 有的一律不做。
   → 增伤、减伤、吸血、点燃、反弹、时运、经验加成、攻速 —— 全部剔除。
2. **它改变的是打法，还是只是数字？**
   → 只改数字的不做。改打法的才留：溅射改变站位、蓄势改变出手节奏、刻痕改变持久战、替身改变送死成本。
3. **能不能用一句话说清「你应该因此改变什么行为」？**
   → 说不清就是数值皮肤。

按这三条筛，最后剩 12 条。

### 二、12 条机制

**武器侧（6 条）—— 改变你什么时候出手、站在哪、打谁**

| 名称 | 机制 | 你应该改变什么 |
| --- | --- | --- |
| **崩流** | 命中时对目标 3 格内的其它敌人造成 40% 溅射（上限 4 个） | 拉到怪堆里打；单体目标时这条没用 |
| **烬狱** | 击杀目标时尸身爆燃，3 格内 6 点固定伤害 + 点燃 | 收人头会有额外收益，适合清小怪 |

| **蓄锋** | 距上次命中超过 2.5 秒时，这一击 +25% | 别乱挥；等时机再砍 |
| **夺魄** | 命中使目标减速 + 虚弱 2 秒 | 追人 / 打断节奏 |
| **刻痕** | 对同一目标累计削掉其三成血后刻印，此后对其 +10% | 打厚血目标越打越痛；打杂鱼白费 |

### 三、为什么这些不可能变成「打不死」或「一刀秒」

机制型附魔真正的风险不是数字不好看，而是**组合起来会崩**。逐个堵：

| 风险 | 堵法 |
| --- | --- |
| 溅射递归放大（溅射再触发溅射） | 溅射走 `LivingEntity#damage` 且**不再进本插件的附魔链路**，只对非玩家目标结算 |
| 卸力叠成免伤 | `max-delay-ratio: 0.50`，且四件护甲**合并后只取最大值再夹一次**（不是各自夹完相加成 200%） |
| 替身变成永久免死 | 冷却是硬性的 `cheat-cooldown-ms: 90000`；回气上限 30%，永远回不满 |
| 延后伤害又把人打死 | 延后分期同样走一遍替身检查 |
| 条件增伤变常驻 | 三个条件（孤锋/蓄锋/刻痕）**任一不满足就归零**，且相加后再夹一次 |
| 刻痕表内存泄漏 | 目标死亡/消失时 `EnchantState.clearMark` 必须清；玩家下线整条清 |
| 望气刷屏 | 节流到每 3 秒一次，走 actionBar 不走聊天框 |
| 烬狱误伤玩家 | 只炸非玩家生物；玩家击杀怪物时不波及玩家 |

离线实测（`java -cp target\classes com.forgemaster.tools.NumericSim`）：

```
条件增伤合计 50.0%（孤锋 15% + 蓄锋 25% + 刻痕 10% + 回响 15%）
崩流 23.9 点（主线 59.8 的 40%）｜烬狱 6.0 点固定｜夺魄 2.0s
卸力摊 50%（四件合并后）｜替身回气 30% 生命 / 冷却 90 秒
满配 59.8 × (1+50.0%) = 89.7 → 夹子后 60.0 → 坚守者 9.0 刀
```

**把 12 条机制全部拉满、四个条件同时满足，伤害仍然被压回 60 点上限，坚守者还是要 9 刀。**
新机制不等于免检通道 —— `combat.limits` 永远是最后一道。

## 十四·补二、v2.23.1：全面查错与修复（两条 P0、二十余条 P1/P2）

### 一、四条 P0

| 缺陷 | 机制 | 修法 |
| --- | --- | --- |
| **崩刃把护甲词条的属性一起摘掉，修好也回不来** | `Attrs.isBaseKey` 用**前缀**判断基础属性键（`startsWith("fm_armor_")`），而 `armor_plate` / `tough_plate` 写出的键是 `fm_armor_plate_chestplate` —— 前缀命中 → 崩刃时被当成基础属性摘掉；修复链只重建 `fm_armor_<部位>`，词条数值只存在修饰符里，摘掉即永久丢失，而 Lore 与词条表还在显示。注释写的是「键名精确匹配」，实现却是前缀，**注释骗人在先**。 | 改成精确白名单（四个裸键 + 八个部位键）。词条键从此不可能被误判，新增词条 id 也不会复现同一类缺陷。同一处判定同时修好了重铸 / 词条符移植「旧值删不掉、新值另挂一条 → 属性叠加」和「`*_plate` 被拦死变成 0」。 |
| **铁砧 `anvils.yml` 异步冲刷：取剑后崩溃 = 复制，放剑后崩溃 = 吞** | 两处叠加：① `saveTo` 是 `synchronized`，但主线程 `sessions.put/remove` **完全不加锁** —— 锁保护不到被保护对象，异步拍快照会撞 `ConcurrentModificationException`，而 Bukkit 的重复任务一旦抛异常就**永久取消**，此后全部砧位失去持久化；② 写盘用的是进入方法时的快照，写完**无条件** `dirty = false`，写盘窗口内玩家的取出被当作已保存。 | 结构变更与「拍快照」段共用同一把锁（`putSession` / `removeSession`），写盘移出锁外；新增**脏代数** `dirtySeq`，只有「写完时代数没再变过」才清脏；写失败保留 dirty 等下一轮。 |
| **属性滚雪球：越强化越离谱，生存服直接没法玩** | `StrengthenService.baseOf` 的优先级是「PDC 快照 → **物品上现有的基础 modifier 原值**」，注释写着「老物品的基础 modifier 是等级 0 时的原值」——**这句话是错的**：modifier 里存的是 `base × mult(当前等级)`，早被倍率乘过。于是老物品（无快照）每强化一次就是 `(base×mult(N)) × mult(N+1)`，而且这个虚高值还被当成新快照写回去，**污染永久化**，下一锤再乘一次。 | 天花板规则：基础值一律 `min(取到的值, 配置算出的基础值 × strengthen.base-tolerance)`（默认容差 1.0 = 严格按配置）。有快照用快照、无快照则用 `modifier ÷ 当前倍率` 反推、都没有用配置值 —— 三条路全部过天花板，**只压虚高、不抬正常值**。存量膨胀物品用 `/zhujian fixattrs [all]` 收敛。 |

### 二、数值超标（服主实测「一刀 130、四刀一只坚守者、一刀吸半管」）

先把这条链子摊开。问题不在某一处配置写错，而在**四层乘区各自都合理、叠起来失控**，且其中最狠的两个环节完全没有上限：

```
基础攻击  5.25（星陨）× 5.0（神话品质）      = 26.25   ← 已是原版下界合金剑(8) 的 3.3 倍
× 强化    (1 + 99×0.006)                    = 1.594
× 蜕变    1.06×1.07×1.09×1.10×1.12×1.15     = 1.752
× 暴击    1.5 + 2.5                         = 4.0     ← 有上限，但上限本身过高
× 吸血    0.14 × 1.65 × 5 条                = 1.155   ← **完全没有上限**
```

| 超标项 | 原值 | 现默认 | 依据 |
| --- | --- | --- | --- |
| 攻击属性 `fm_atk` | 无上限（满配实测 ≈73） | `max-attack-attribute: 22` | 原版下界合金剑 = 8，压在约 2 倍 |
| 单次伤害 | 无上限（130+） | `max-hit-damage: 60` | 坚守者 500 血 → 满配约 8–9 刀，中档约 18 刀 |
| 暴击倍率 | ×4.0（`1.5+2.5`） | ×2.6（`1.5+1.10`） | 略强于原版跳劈 ×1.5，不再是乘法放大器 |
| 暴击率 | 75% | 50% | 75% 等于「刀刀暴击」，暴击从惊喜变成默认值 |
| 吸血比例 | 无上限（115%） | `max-lifesteal: 0.20` | 三道夹子取最小 |
| 单次吸血回血 | 无上限（近半管） | 2 点（一颗心） | 绝对值夹 + 血条 10% 夹 |
| 气血（生命上限） | 无上限（单件 +41） | `max-bonus-health: 20` | 本轮新发现，20 血变 61 血＝肉盾 |
| 点燃时长 | 无上限（5 条 40 秒） | `max-fire-seconds: 10` | 目标早死了，纯浪费性能 |

**关键实现细节**（改的时候别踩回去）：

- 伤害上限必须夹在**暴击之后**。夹在前面的话暴击照样能把数字顶穿，等于没管。
- 攻击属性上限落在**产出**处（`apply()` 写 `fm_atk` 前），所以 Lore、属性面板、实战三者永远同一个数，不会「面板很高、打出来被砍」。
- 吸血写入端也夹（`ItemFactory`）。原来 PDC 存 115%、实战只回 20%，玩家会当 bug 报上来。
- 暴击率有 `1.0` 硬天花板，**配置写 5.0 也不允许「必定暴击」**——这是代码级的不变量，不是可调项。

升级时的行为：`config-version` 15→16 会在首次启动补上 `combat.limits.*` 8 个键；暴击上限**只在仍是旧默认值（0.75 / 2.5）时才下调**，你自己调过的值原样保留（迁移不覆盖人工调参）。

### 五、旧装备怎么处置（服主必读）

**产出侧的夹子管不到盘上的旧东西。** 玩家把那一刀 130 的剑挂在墙上供着，它就永远是 130；生存服上这等于给少数人留了外挂。所以做了主动收敛，三个触发点覆盖三类位置：

| 触发点 | 覆盖范围 | 说明 |
| --- | --- | --- |
| `/zhujian fixattrs` | 手持那一件 | 先验证数字对不对 |
| `/zhujian fixattrs all` | 在线玩家（背包 + 盔甲 + 副手 + 末影箱） | 人齐时跑一次立刻见效 |
| `/zhujian fixattrs containers` | **已加载**区块里的箱子/木桶/熔炉… | 不为了修物品强制加载世界 |
| **玩家上线自动扫** | 该玩家全部随身物品 | `legacy-repair.on-join`，默认开 |

**为什么离线玩家靠「上线」而不是「开服扫全服」**：离线背包在 `world/playerdata/<uuid>.dat` 里。一开服就扫所有人，要么自己解析 NBT（容易写坏存档），要么强行加载每个玩家档案（内存打满）。而玩家登录时服务端本来就要加载他的档案 —— 这时候扫一遍零成本，效果等价：不管他多久没上线，只要有一天上线，身上就已经是收敛后的数值。**能拿这把剑去打架的，本来就是已经上线过的人。**

**扫完之后 Lore 具体变什么**（这是服主最该先弄清的）：

| Lore 行 | 会变吗 | 说明 |
| --- | --- | --- |
| 词条行（+115% 吸血、燃烬 8 秒…） | **不变** | 数值在锻造时就化成文字，盘上只存词条 id 不存每条的 roll 值，没法反推 |
| 锻造等级 ▸ +N/+CAP (基础属性 +X%) | **不变**（v2.23.1 起） | 收敛走 `applyStatsOnly`，不再重建这一行；+N 与百分比本来也不受上限影响 |
| 锻阶 / 履历 行 | **不变** | 同上，收敛不再碰这两行 |
| **◆ 已收敛：…** | **新增一行** | 只列**这次真的被压过**的项，如「吸血 20% · 气血 20」 |

所以玩家看到的是：词条字还是旧的，底下多一行说明「哪几项按上限压过了」，以及「重铸可刷新」。

收敛时会做什么：

```
基础属性（攻/速/甲/韧）→ 按当前配置重算（走已被天花板保护的路径）
吸血 PDC 1.155        → 0.20
点燃 PDC 800 tick     → 200 tick（10 秒）
减伤 PDC 0.58         → 0.35
气血 modifier +41     → 按比例缩到 20（保留各条的键，不破坏词条身份）
```

**一个必须说清的取舍：Lore 文本无法完美重写。** `affix_list` 只存词条 id，**不存每条 roll 到多少** —— 数值在锻造那一刻就化成了 Lore 文字，盘上没有记录。所以「+115% 吸血」这行字没法按比例算回「+20%」（两个吸血词条各 roll 了多少，无从考证）。

因此收敛的做法是**把生效值夹住 + 在 Lore 末尾打一行说明**，而不是留一句看起来像 bug 的落差。想要 Lore 本身也干净，拿它重铸一次即可（重铸会按词条池重新生成整块 Lore）。

### 六、新增内容（拓展 C + 切片 2/3 接线）

**P0：成品界面「取不回 / 剑消失」已修**（服主报的「点拿走没反应，ESC 一关剑就没了，不是每次都触发」）：

根因是 `ForgeManager.open()` 里 `transitioning` 被**同步**清掉，而旧界面的 `InventoryCloseEvent` 常常**下一 tick**才送达。迟到的关闭事件看到 `phase == RESULT`，就把会话当成「玩家关了成品界面」销毁了 —— 于是界面上还在、点不动、关掉后展示副本消失。

修法不赌时序：① 加纯函数 `isTransitionClose()`，看「玩家此刻打开的是不是同一会话的另一张界面」；② `transitioning` 改下一 tick 再清；③ `onClick` 加兜底 `reclaim()`，会话已结算也照样能把成品拿走。

顺带修掉一个**永久丢东西**的隐患：`giveResult` 原来是「先标记已发放、再塞背包」，中途抛异常就等于把剑永久吞了。改成**先发放、后打标记**，并 `clone()` 后再塞（同一 ItemStack 同时被放在成品格展示，给背包的必须是独立副本）。

**第二轮检修修掉的三个真 bug**（全是「同一个默认值/标志存在两份」这一类）：

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| **重载插件后重铸界面点不动** | `ReforgeMenu.listenerReady` 静态标志从不清零，新实例不再注册监听器 | 新增 `ReforgeMenu.reset()`，挂在 `onDisable` 与八个 GuiRouter 同位置 |
| 线上按暴伤上限 2.5 算、自检按 0.75 断言 → 自检必红 | `Crit.resolve(2参)` 与 `fromConfig` 各写一份默认值 | 两处统一转调 `Limits.defaults()` |
| 改上限时漏改一处 → Lore 显示 20%、实战夹 15% | `0.20/0.35/20.0/10.0/22.0` 被四五个模块各写一遍 | 新增 `DamageBudget.Caps.fromConfig()`，所有调用点只走这一处 |

另外拆出了 `StrengthenService.applyStatsOnly(item)`：只重算属性、**完全不碰 Lore**。存量收敛现在走这条路 —— 玩家看到的改动范围就真的是改动范围，不会「只超了吸血，等级行却被重建一遍」。

- **数据看板切片 2/3 真正上线**：`MetricsService` 此前只在包里躺着，主类从未构造它 —— 历史趋势 / CSV 导出永远不会跑，`metrics.history-days` 改了也没反应。现在接上生命周期，并新增四个子命令：
  - `/zhujian admin metrics` —— 实时体检（与 v2.20 完全一致，老用法不变）
  - `/zhujian admin metrics trend [天数]` —— 逐日产出/消耗/净额/锻造/碎裂 + 趋势总结
  - `/zhujian admin metrics csv [天数]` —— 导出 CSV 到 `metrics-export/`
  - `/zhujian admin metrics sample` —— 立刻采一次样
  - `/zhujian admin metrics gui` —— 打开**三页 GUI**（实时体检 / 近况趋势 / 分配分布），翻页与刷新都在面板里；内容行铺成纸片，悬浮可读全文，与文本命令同一套口径
- **出站 Webhook 播报（`webhook.*`）**：有界队列 + 独立守护线程 + 每类事件 10 秒限流 + 连续失败 5 次熔断 60 秒，主线程零 IO；JSON 手写转义（零第三方依赖）。默认关闭，`url` 留空即空壳。**八类事件全部插桩**：锻造成功 / 强化成功 / 碎剑 / 蜕变成功 / 剑冢胜利 / 比试获胜 / 行会委托达成 / 赛季结算；统一走 `plugin.broadcast(...)` 入口（内部 try 掉一切，播报永不抛回业务路径）。
- **战力评分 `PowerScore`（路线图切片 5 · D）**：
  ```
  power = 基础(品质×材质) × 强化 × 蜕变 × 词条 × 宝石 × 剑灵
  ```
  用**乘法**而不是加法：强化到高段本身是门槛（材料贵、碎剑风险）、蜕变不可逆，加法会让「+20 词条稀烂」和「+2 满词条」同分，跟玩家体感完全不符。每一项系数都钳在小范围（强化上限 8 倍），不会出现「一项爆表压死其它项」。
  - **权重全部走配置** `power-score.*`：每一项系数、每个词条的贡献值、评级分界都能改，`/zhujian reload` 立刻生效。代码里只有「能跑起来」的保守初值——路线图要求等切片 1-3 跑两周、看清「什么配置的剑真的有人抢」再按真实成交校准。
  - `/zhujian power` 看手持剑的**拆解**（分数 / 品质材质 / 强化蜕变词条 / 宝石附魔 / 推荐价）——不解释的黑盒分数没人会信。
  - 推荐价 = 战力 × `price-per-power`，取整到 10 的倍数，受 `price-min` 兜底，可一键关闭。
  - **已接进玩家侧**：拍卖条目 Lore 直接显示「战力 + 评级 + 参考价」，当前价偏离参考价一倍时标「偏高 / 偏低」；挂单成功的提示里追加「这件战力 X（评级），参考价 Y」；订单发单成功后同样追加样品定价提示 —— 定价不再凭感觉。
  - **防刷**：只读物品自身 PDC（材料/品质/强化/蜕变/词条/宝石/灵性，全部服务器写入），且不做任何跨物品累加——「复制一堆剑堆分」这条路不存在。
