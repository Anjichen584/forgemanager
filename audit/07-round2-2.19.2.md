## 二、P1-1 / P1-2：整段缺失（这轮最有价值的发现）

### 怎么发现的

写了个脚本，把 `settings().num/intOf/flag/str/strList` 的**字面量实参**收集起来，
跟 `config.yml` 的键树比对。第一版只比了"代码读的键"，报出 17 个，
其中 10 个是动态拼接前缀（正常），剩 7 个是真裸键。

但真正的问题在第二版：**拿内置 `config.yml` 的全部节点跟测试服盘上的比**——

```
资源里 1374 个节点，盘上缺 187 个
整段缺失（该段一个节点都不在盘上）：
  !!! blackmarket    codex      daily      dissolve   guild
  !!! hall           order      placeholder relic-set season-pass
  !!! spectrum       titles     tombrun
```

### 为什么以前没炸

因为大部分段代码里都有兜底。`getConfig().getInt("x.y", 默认值)` 这种写法天然容错。

**但黑市是个例外**：

```java
// BlackmarketService:249
private List<PoolItem> pool() {
    for (Map<?, ?> raw : plugin.getConfig().getMapList("blackmarket.pool")) { ... }
}

// BlackmarketService:88
public List<Offer> offers() {
    List<PoolItem> pool = pool();
    if (pool.isEmpty()) return out;     // ← 空列表，直接返回空
    ...
}
```

`getMapList` 没有默认值重载，盘上没有这段 → 空列表 → `offers()` 恒空。
玩家敲 `/zhujian blackmarket`，界面正常打开、价格区正常渲染，**货架一件货都没有**，
日志一声不响。这是"静默死功能"里最难查的那一类。

### 修法：step15 整块自愈

原则：**只补「盘上完全没有」的东西，段里只要有一个键存在就整段不碰。**

```java
for (String path : res.getKeys(true)) {        // 按字典序遍历内置资源
    if (disk.contains(path)) continue;        // 盘上有 → 服主在管
    if (coveredBy祖先) continue;              // 祖先已整块补过
    if (是段)  { 把段内所有叶子拷过来; 记入 coveredBy; }
    else      { cfg.set(path, res.get(path)); }   // 标量 / 列表
}
```

三个细节：

1. **列表也要认**。`titles` 在资源里是个**顶层列表**，第一版只处理
   `ConfigurationSection`，导致 `titles` 补了 0 个键（日志里 `titles(0键)` 就是这个）。
2. **最浅节点优先**。`mentor` 段存在但 `mentor.graduation` 整块缺失 →
   应该补 `mentor.graduation` 这棵子树，而不是逐个补它下面的 11 个叶子。
3. **纯空段也要建**。`createSection` 一下，否则 `contains()` 仍是 false。

实测效果（测试服，config-version 5 → 6）：

```
step15：盘上缺 14 处配置（共 41 个键），已按内置默认整块补回 ——
  strengthen.kindle(1键)、anvil-forge.display.sword-growth-curve、
  contract.tax.event-multiplier、forms.yuehen(4键)、forms.qianchuiwen(4键)、
  imprint.merge(4键)、compat.attack-speed-cap、mentor.graduation(11键)、
  events.schedule、events.types.dragon-tide(3键)、spirit.display(7键)、
  tomb.page-discount-per、tomb.page-discount-max、titles
```

复查：**资源 1374 个节点，盘上缺 0 个。**

> 注意 step15 是按 `config-version` 一次性跑的。要重新触发（比如怀疑补漏了），
> 把盘上 `config-version` 改小一号再重启即可。

## 三、P1-3：附魔镶嵌「显示 200，实扣 300」

比对了所有 `gems.*.cost-coins` 键的"读显示"和"读扣费"两处：

| 键 | 显示处 | 扣费处 |
| --- | --- | --- |
| `gems.socket.cost-coins` | ForgeMenu:854 | GemService:389 |
| `gems.smelt.star-cost-coins` | ForgeMenu:885 | GemService:326 |
| `gems.inlay.cost-coins` | ForgeMenu:893 | GemService:837 |
| `gems.extract.cost-coins` | ForgeMenu:909 | GemService:903 |
| `gems.merge.cost-coins` | ForgeMenu:917 | GemService:716 |
| `gems.enchant-socket.cost-coins` | ForgeMenu:858 | GemService:475 |
| **`gems.enchant-inlay.cost-coins`** | **ForgeMenu:901** | **（无人读）** |
| `gems.enchant.cost-coins` | （无人读） | GemService:1114 |

前六项都是"显示=实扣"，只有附魔镶嵌这条读了两个不同的键：
GUI 读 `enchant-inlay`（盘上没有 → 回退 200），实扣读 `enchant`（配置里 300）。

玩家看到"费用 200 剑币"，点下去扣 300。改回同一个键。

顺带把这类错位的守门补上：**所有必需键都必须在 jar 内置的 config.yml 里**
（见第五节断言 1）——这样 `enchant-inlay` 这种孤儿键在任何地方出现都会红。

## 四、数值：蜕变第 6 阶是「白贵」

### 现象

```
现状   阶1 ×1.08 95%   期望 1.05 次      632 剑币
       阶2 ×1.08 88%   期望 1.14 次    1,704
       阶3 ×1.10 78%   期望 1.28 次    5,116
       阶4 ×1.10 66%   期望 1.49 次   13,454
       阶5 ×1.12 52%   期望 1.82 次   36,420
       阶6 ×1.12 40%   期望 2.18 次   97,920   ← 乘区与阶5 完全一样
       合计 155,246 剑币 ≈ 1,522 把 FINE 剑，总乘区 ×1.770
```

乘区表是 **1.08/1.08/1.10/1.10/1.12/1.12**——成对重复，全表只有三个不同值。
第 6 阶花 97,920 剑币（**成功率的保底让期望次数涨到 2.18**），
换来的乘区增益是 **×1.00**，只剩称号和全服播报。

### 改法

乘区改成严格单调，**总连乘守住原值**（2.17.3 那条"别再叠"的约束照旧）：

| 阶 | 旧乘区 | 新乘区 | 旧费用 | 新费用 |
| --- | --- | --- | --- | --- |
| 1 精钢 | 1.08 | **1.06** | 600 | 600 |
| 2 寒钢 | 1.08 | **1.07** | 1500 | 1400 |
| 3 流星 | 1.10 | **1.09** | 4000 | 3000 |
| 4 传世 | 1.10 | **1.10** | 9000 | 6000 |
| 5 不朽 | 1.12 | **1.12** | 20000 | 12000 |
| 6 造化 | 1.12 | **1.15** | 45000 | 24000 |

连乘 **×1.752**（旧 ×1.770，差 1%，可忽略），总费用 **155,246 → 89,105**
（1,522 → 874 把 FINE 剑，-43%），且**每一阶都有真增益**。

### 图纸价格

星陨图纸 1600，护胚符 1500。护胚符能救一条命，图纸只给一次性 +15% 加热容差——
性价比顺序反了。压平成：

| | iron | gold | copper | diamond | netherite | starfall |
| --- | --- | --- | --- | --- | --- | --- |
| 旧 | 120 | 150 | 260 | 480 | 900 | **1600** |
| 新 | 120 | 150 | 240 | 360 | 560 | **800** |

星陨图纸现在 800（7.8 把剑的产出），低于护胚符 1500，也低于自己一次锻造费 5000。

黑市池里的图纸原价同步改了（否则黑市打完折还比商会贵）。

## 五、自检新增 5 条

1. **内置 config.yml 含全部必需键**：直接对 jar 里的资源校验 181 个键。
   构建产物本身漂了就红——这条能拦住 P1-3 和所有裸键问题。
2. **隐形键已落盘**：重铸品质乘区 / 工序提示 / 失败留档 / 防御词条池。
   同时校验值仍等于代码默认（补键不得改变行为）。
3. **蜕变乘区严格单调**：逐阶 `b > prev`，且连乘落在 1.70~1.80（守住重定后的总乘区）。
4. **图纸价格阶梯**：单调递增，且星陨图纸价 < 护胚符价。
5. **整段缺失的配置段已被补回**：`blackmarket.pool` 非空 + `offers()` 非空 +
   `codex`/`spectrum`/`guild`/`relic-set`/`titles` 段存在。

第 5 条是这轮的"活体证据"：它直接复现老服的坏状态，修完后转绿。

## 七、迁移链现状

`config-version` 1 → **6**。这轮加了三个 step：

| step | 内容 | 判定 |
| --- | --- | --- |
| 13 | 补 12 个裸键（重铸权限/确认/词条池/品质乘区、工序提示、失败留档、货币口径） | `putIfAbsent`：盘上缺才写，值 = 代码默认 |
| 14 | 蜕变六阶乘区/费用 + 图纸价 + 黑市池原价 | 逐项比旧默认，等于才改 |
| 15 | 整段/整块缺失自愈 | 盘上完全没有才补 |

三者都不改变"服主调过的值"，语义与前 12 个 step 一致。
