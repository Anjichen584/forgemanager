## 三、货币、锻造费与装备（v2.0 / v2.1）

剑币是本插件的唯一货币，所有增减都走 `StatsStore.addCoins` / `takeCoins`，玩家数据按 UUID 存放。

### 来源

| 来源 | 计算 | 配置 |
| --- | --- | --- |
| 锻造成功 | (`forge-base` + 品质序号×`forge-per-quality` + 分数×`forge-per-score`) × 连锻倍率，至少 1 | `coins.*` |
| 连锻倍率 | 第 N 连 ×(1 + 0.15(N−1))，上限 ×3 | 代码 `StatsStore.streakMultiplier` |
| 委托交货 | `commission-base` + 声望奖励×`commission-per-rep`（不乘连锻） | `coins.*` |
| 大赛名次 | 第 1/2/3 名 300/180/100，第 4 名起 40 | `coins.contest-*` |
| 师徒分成 | 徒弟锻造收益 × `mentor.coin-share-rate`（默认 10%，至少 1） | `mentor.*` |
| 成就奖励 | 各成就的 `coins` | `achievements.list.*` |
| 剑冢挑战胜利 | `challenge-win-coins` | `tomb.*` |
| 拍卖行 | 卖家收到成交价扣抽成（抽成销毁） | `auction.*` |

### 用途

| 用途 | 说明 | 配置 |
| --- | --- | --- |
| 商会购买 | 原料（铁、金、铜、钻石、下界合金锭）按档次定价；图纸按剑胚定价 | `shop.*` |
| 图纸加成 | 背包里有对应剑胚的图纸 → **加热容差 +15%**，打一把消耗 1 张 | `blueprint.*` |
| 拍卖行 | 竞价与一口价；加价有最小步长，单件有上限 | `auction.*` |
| 剑灵喂养 | 每次花费剑币，增加灵性 | `spirit.feed-coin-cost` |
| 剑冢 | 埋剑、取回（可收费）、挑战（不退还） | `tomb.*` |
| 锻造费 | 每次开锻按档位扣 200 / 400 / 500 / 1000 / 2000 / 5000 | `materials.*.price` |

### 锻造费走服务器经济（v2.1）

开锻时先扣**锻造费**，再扣耗材；扣费成功后才动材料，材料扣除异常会自动退费。

| 档位 | 剑胚 | 锻造费 | 耗材 |
| --- | --- | --- | --- |
| 1 | 铁剑 | 200 | 铁锭 ×8 |
| 1 | 金剑 | 400 | 金锭 ×8 |
| 2 | 铜剑 | 500 | 铜锭 ×10 |
| 3 | 钻石剑 | 1000 | 钻石 ×6 |
| 4 | 下界合金剑 | 2000 | 下界合金锭 ×4 |
| 5 | 星陨剑 | 5000 | 铁块 / 金块 / 铜块 / 钻石块 / 下界合金块 各 1 |

货币后端按 `economy.provider` 自动选择（默认 `auto`）：

1. **Vault** —— 装了 Vault 且任意经济插件注册了 Vault 经济（CMI / EssentialsX / Craftconomy…）时优先走 Vault。
2. **CMI** —— 没有 Vault 但装了 CMI 时，直连 CMI 的 `EconomyManager`。
3. **内置剑币** —— 两者都没有时，扣插件自己的剑币，避免单人服没法玩。

两种外部接口都是用反射调用的，插件**不硬依赖** Vault / CMI，没装也不会报错。

#### 两本账别混用（v2.19.1）

上面那句「剑币是唯一货币」有个**唯一例外**：锻造费走服务器经济。除此之外，
宝石 / 黑市 / 签到 / 重铸 也一度错走了服务器经济，导致「剑币明明够却提示不足」。
现在全部收口到 `com.forgemaster.econ.Wallet`，用 `economy.coin-sinks` 选口径：

| 值 | 含义 |
| --- | --- |
| `plugin`（默认） | 宝石 / 黑市 / 签到 / 重铸 扣**剑币**，与商会 / 拍卖 / 强化同一本账（按本节开头那句设计） |
| `server` | 改扣**服务器经济**（Vault / CMI），适合「想让宝石也吃金币」的服 |

锻造费不受这个开关影响，永远走服务器经济。没装 Vault / CMI 时两条路完全等价
（内置后端本来就是 `StatsStore`），单人服无感。

`/zhujian money` 会把两本账并排打出来（剑币余额 + 当前消费口径 + 锻造费去向），
怀疑口径配错时先敲这一条。

### 锻造装备（v2.1）

主界面拆成总入口，分「锻造武器」和「锻造装备」两条线。

- **部位**：头盔 / 胸甲 / 护腿 / 靴子。
- **档位**：沿用武器的六档，材质自动映射（铁→铁甲、金→金甲、铜→铜甲、钻石→钻甲、下界合金与星陨→下界合金甲）。
- **费用**：与同档武器一致，可用 `armor.price-multiplier` 整体调价。
- **属性**：装备不吃攻击力，改为额外护甲与盔甲韧性，随品质倍率放大；原版护甲值照常显示。
- **词条**：装备只从**防御池**抽，抽不满也不会补武器词条。

防御词条：

| id | 名称 | 效果 | 区间 |
| --- | --- | --- | --- |
| `armor_plate` | 厚甲 | 护甲 | +1.5 ~ +3.5 |
| `tough_plate` | 坚壁 | 盔甲韧性 | +0.5 ~ +1.5 |
| `vitality` | 气血 | 生命上限 | +2 ~ +5 |
| `knockback_resist` | 磐石 | 击退抗性 | +5% ~ +15% |
| `aegis` | 庇护 | 受到伤害减免 | +3% ~ +7% |

`aegis` 是四件套叠加的，但总减免封顶 60%，不会出现无敌。

### 耐久分档（v2.2）

耐久不再是「品质序号 × 40」那种线性值，而是 **胚子基础耐久 × 品质倍数**，两个独立乘区：

| 品质 | 系数 | 1000 基础耐久的成品 |
| --- | --- | --- |
| 粗糙（劣质） | ×0.5 | 500 |
| 普通 | ×1.0 | 1000 |
| 精良 | ×1.5 | 1500 |
| 史诗 | ×2.2 | 2200 |
| 传说 | ×3.0 | 3000 |
| 神话 | ×5.0 | 5000 |

基础耐久按档位配置（`materials.*.base-durability`）：

| 档位 | 剑 | 装备 |
| --- | --- | --- |
| 铁 | 250 | 胸甲同值，头盔 ×0.8、护腿 ×0.9、靴子 ×0.75 |
| 金 | 150 | 同上 |
| 铜 | 300 | 同上 |
| 钻石 | 800 | 同上 |
| 下界合金 | 1300 | 同上 |
| 星陨 | 1600 | 同上 |

也就是一把**神话星陨剑 = 1600 × 5 = 8000 耐久**，而**劣质铁剑只有 125**，修一次的成本差距会非常直观。

> **研磨修复是原地替换**：修好的那把会顶掉背包里原来那件（按材料 + 修复前耐久匹配），不会额外多出一件。如果原物已经不在背包（丢掉/放进箱子），修好的会放回背包而不是凭空复制。

### 宝石（v2.2）

宝石不是「点一下就镶上」的，要走三步：

**一、开孔** `/zhujian gem socket`

- 主手拿锻造品，消耗 `IRON_BLOCK ×2` + 金币 `500 × 已开孔数+1`。
- **孔位上限按材料档位**：铁 / 金 / 铜 1 孔，钻石 / 下界合金 2 孔，星陨 3 孔。品质不再影响孔数。
- 成功率 `100% − 15% × 已开孔数`，最低 35%。**失败只亏材料和钱，不毁物品**。

**二、星熔宝石** `/zhujian gem smelt`

- **唯一原料是下界之星**：主手拿 1 颗下界之星，消耗金币 300，熔出 1 颗随机属性的 **Lv.1** 宝石。
- 钻石、铁、金、绿宝石、烈焰粉这些**都熔不出宝石**，会被直接拦下并提示，不会白白消耗。
- 属性 11 种完全随机（赤玉 / 星辉石 / 破军石 / 焚天石 / 血玉 / 玄铁石 / 金刚石 / 血珀 / 风行石 / 镇岳石 / 疾风石）。
- 等级 **只能从 Lv.1 起步**，往上全靠三合一：一颗 Lv.5 = 3⁴ = **81 颗 Lv.1**（不考虑合成失败）。

| 等级 | 数值倍率 | 折算下界之星 |
| --- | --- | --- |
| Lv.1 | ×1.0 | 1 |
| Lv.2 | ×1.6 | 3 |
| Lv.3 | ×2.4 | 9 |
| Lv.4 | ×3.6 | 27 |
| Lv.5 | ×5.0 | 81 |

**三、镶嵌** `/zhujian gem inlay`

- 主手装备、副手宝石，消耗金币 200。
- 镶嵌后立刻生效：属性类直接加 `AttributeModifier`，暴击/暴伤/吸血/点燃累加到 PDC 汇总值。
- 装备 Lore 里会出现 `◆ 镶嵌孔 [n/m]` 与每颗宝石 / 每条附魔的属性行。

**三·五、附魔镶孔** `/zhujian enchant`

- 主手装备、副手**附魔书**，消耗金币 300，把书上的附魔镶进一个孔。
- **附魔与宝石共用同一组孔位**：1~3 个孔，镶宝石还是镶附魔自己权衡。
- 同一附魔重复镶只升等级，不额外占孔；书上镶不进去的附魔会被跳过，全都不适用则直接拒绝且不扣费。
- 单条附魔等级不超过原版上限（锋利最高 V，不会出现锋利 255）。
- 老装备第一次镶嵌时，Lore 里的旧标题 `◆ 宝石孔` 会自动换成 `◆ 镶嵌孔`，不会留两套块。

`/zhujian gem` 不带参数会打开**宝石台**界面，五个按钮分别对应下面五步，界面里会显示当前主手/副手、孔数、费用与成功率。

**四、拆卸** `/zhujian gem extract`

- 主手装备，取下**最后一颗**宝石，消耗金币 300。
- 成功率 80%，失败宝石碎裂，**装备本身不受损**，孔位照样空出来。
- 拆卸会同时回退属性：属性类移除对应 AttributeModifier，暴击/暴伤/吸血/点燃从 PDC 汇总值里减掉。

**五、合成（三合一）** `/zhujian gem merge`

- **3 颗同级同种**宝石 → 高一级：主手 + 副手 + 背包里自动补第三颗。
- 成功率逐级递减：85% / 65% / 45% / 25%。
- 失败保留一颗原档，不会三颗全没；**Lv.5 封顶**，不能再合。

宝石共 11 种：

| 名称 | 属性 | 类型 |
| --- | --- | --- |
| 赤玉 | 攻击力 | 原版属性 |
| 星辉石 | 暴击率 | 自定义 |
| 破军石 | 暴击伤害 | 自定义 |
| 焚天石 | 点燃时长 | 自定义 |
| 血玉 | 生命偷取 | 自定义 |
| 玄铁石 | 护甲 | 原版属性 |
| 金刚石 | 盔甲韧性 | 原版属性 |
| 血珀 | 生命上限 | 原版属性 |
| 风行石 | 移动速度 | 原版属性 |
| 镇岳石 | 击退抗性 | 原版属性 |
| 疾风石 | 攻击速度 | 原版属性 |

这套流程对标 PlayerGem：开孔 → 熔炼 → 镶嵌 → 拆卸 → 三合一，宝石不是一次性消耗品，可以反复倒腾。

### 原版交互封禁（v2.4）

附魔和修理全部收进锻造体系，原版附魔台与铁砧被封掉：

| 原版行为 | 封掉之后 |
| --- | --- |
| 右键附魔台 | 拦截，提示改用 `/zhujian enchant` 把附魔书镶进孔里 |
| 右键铁砧（三种铁砧都算） | 拦截，提示修剑用 `/zhujian repair`、强化用 `/zhujian strengthen` |
| 附魔台 / 铁砧界面 | 打开即被关掉，用别的插件或命令方块强开也一样 |
| 界面里点击 | 整格锁死，塞物品也塞不进去 |
| 附魔 / 铁砧合成事件本身 | 最后一道：即使前面全被绕过，附魔不生效、铁砧结果被清空 |

**四道拦截**从「交互 → 开界面 → 界面点击 → 事件本身」全堵，照粘液科技那套思路做的——只挡右键，玩家换个方式（别的插件开界面、漏斗/村民操作、模组客户端）照样能进，所以每一层都要单独堵，任何一层漏了其余三层兜住。`vanilla-guard.block-events: false` 可以只留前两道。

**兼容性上要注意的两点**：

- **潜行 + 右键铁砧开锻造台的快捷键照样能用**。守卫对这条路显式放行：`ForgeListener` 是 NORMAL 优先级、守卫是 HIGH，它先执行并取消事件，守卫靠 `ignoreCancelled` 跳过；即使将来有人改了那边优先级，守卫里也有一条显式放行做双保险。
- **插件自己的锻造演出只用铁砧方块本身，不打开铁砧界面**，所以封禁不影响锻造流程。

砂轮默认**不封**（`grindstone: false`），需要就改 `true`。三个提示文案都可配置。

### 反作弊兼容（v2.2）

Vulcan / Grim / Matrix 这类反作弊的 Velocity Check 是拿「玩家实际移动」对比「预期速度」来判定的。插件给玩家加移速、或者让攻击者击退远强于原版时，反作弊若按原版公式算预期值，就可能误判成 Velocity。

启动时会探测 Vulcan / Matrix / Grim / Spartan / Themis / Negativity / Verus，命中就把两类加成收敛：

| 属性 | 检测到反作弊 | 没检测到 |
| --- | --- | --- |
| 移动速度 | ≤ 5% | ≤ 35% |
| 攻击击退 | ≤ 0.6 | ≤ 2.0 |

只压这两类，护甲、生命、暴击、吸血这些不影响移动判定的照旧。`compat.anticheat-aware: false` 可以整个关掉。

> 实测环境里 Vulcan 已识别并输出 `检测到反作弊 Vulcan，已启用属性兼容：移速上限 5%，击退上限 0.60`。但「会不会真的被判 Velocity」需要真人客户端跑动才有结论——插件侧只用了原版 Attribute，不碰位置/速度包，这是最不容易被误判的做法。
