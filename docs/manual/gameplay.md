## 二、玩法流程（锻造核心）

一道剑走五关，每关独立打分，最后加权。

### 1. 加热（控温）
- 铁砧上演出一把剑 + 一把锤；附近 4 格内有真铁砧就用真铁砧，没有则临时生成 `BlockDisplay` 替身（不放置真实方块）。
- 操作：左键「拉风箱」+8°（0.2 秒冷却）、左键「取出剑坯」进入锻打、左键「放弃锻造」（材料不退还）。
- 温度每秒自然下降约 1.5°（`heat-decay-per-tick: 0.075` ×20），每种剑胚有最佳区间；偏离线性扣分，超过 112° 加热分 ×0.35。

### 2. 锻打（节奏敲击）
- 9 格轨道，指针来回弹跳，绿色为命中区：正中完美（1.0）、边缘良好（0.78）、偏出（0.08）。
- `zone-width` 越大绿区越宽。

### 3. 叠钢（序列连点）
- 按界面给出的序列（如 `3 → 7 → 1 → 5`）依次点对应格。点对 +1 层，点错罚 0.6 秒，错满 3 次中断，超时按已点对比例结算。
- 层数决定钢纹（直纹、水波纹、雪花纹、羽毛纹）写进 Lore。序列长度随剑胚阶级，3–9 层。

### 4. 开刃（控压保持）
- 把压力值稳在随机绿区内，压力会自己漂移；「加压」+6、「减压」−6。持续 `grinding-duration-ticks`，按在绿区的 tick 比例给分。
- 按钮位置：界面**左上角铁块 = 加压**、**右上角羽毛 = 减压**（轨道占 9~17 格，按钮只能放在第一行两端）。研磨修复用的是同一套界面。

### 4.1 抛光（光泽下刀，v2.19）
- 一条 0~100 的光泽标尺，指针每 tick 按 `polishing-speed` 往返扫动（默认 2.6 个百分点），碰到两端自动掉头。
- 标尺上有一段**亮区**（中心与半宽都随机，半宽默认 16），点「下刀」一格 = 一刀；共 `polishing-passes` 刀（默认 3），每刀之后亮区重新抽位置。
- 一刀的成色按偏差给：偏差在半宽一半内是满分 1.0，到**两倍半宽**归零，中间线性过渡——亮区边缘不是断崖，但乱点也拿不到分。
- 指针每 tick 都会做差量重绘（只改变化的格），亮区内会提示「就是现在，下刀！」。
- 兜底：`刀数 × 6 秒 + 4 秒` 到点自动收工，**没下的刀按 0 摊平**（先下了 1 刀满分再超时收工，成色是 1/3 而不是 1.0）。

### 4.2 嵌银丝（亮窗抢点，v2.19）
- 9 格轨道上依次亮起 N 根银丝（根数 = `inlay-length` 基础值 + 材料档位加成，夹在 2~8），相邻两根不会落在同一格。
- 每根银丝有一个**亮窗**（默认 14 tick，档位越高越短，下限 5 tick）。亮窗内点中那一格才算嵌上，亮窗灭了记失手并换下一根。
- 点错格**不推进**，但亮窗立刻缩短 3 tick——乱点会被反过来惩罚。
- 成色 = 命中率 − 失手 × 0.05，夹在 0~1；HUD 上有一条亮窗倒计时条，快灭时变橙。
- 兜底：`根数 × 亮窗 × 3.2` 毫秒 + 2 秒。

### 4.3 两道工序都可在 config 里单独关掉
`settings.polishing-enabled` / `settings.inlay-enabled` 置 `false` 即整段跳过，**权重按比例让给其它工序，总分仍是 100**（见下一节的归一说明）。

### 5. 淬火（选介质）
五种介质（水、油、血、冰、魂）各有评分加成与词条池；选定后成品实体替换铁砧上的剑胚。

### 6. 结算
```
总评分 = (加热×20 + 锻打×35 + 叠钢×20 + 开刃×10 + 抛光×8 + 嵌银丝×7 + 淬火×(0~15)) ÷ 总权重 × 100
```
总权重默认 115（20+35+20+10+8+7+15）。**关掉某道工序只把它从权重总和里摘掉，不做固定偏移**：剩下的工序按各自权重占比重新归一，所以七工序全满配是 100、只开四道也还是 100、全 0 还是 0。材料档次再乘上限（精炼 +6%，天外 +12%），再乘档位压分（每高一档 −1.5%），最后定品质。

| 评分 | 品质 | 词条数 | 属性倍率 |
| --- | --- | --- | --- |
| < 35 | 粗糙 | 0 | ×0.55 |
| 35+ | 普通 | 1 | ×0.80 |
| 55+ | 精良 | 2 | ×1.00 |
| 72+ | 史诗 | 3 | ×1.22 |
| 86+ | 传说 | 4 | ×1.45 |
| 95+ | 神话 | 5 | ×1.75 |

七道工序全满分 → 额外 +1 词条；专精够高有概率再 +1（上限 6）。传说以上全服广播。

### 6.1 词条数值按材料档位分档（v2.4）

同一条「锋锐」，铁剑抽出来和星陨抽出来不再是一个区间。每个档位有两个系数：

- **value**（数值倍率）—— 决定基准有多高；
- **spread**（波动倍率）—— 决定上下浮动有多宽。

最终值 = `(min+max)/2 × value ± (max-min)/2 × spread`。

| 档位 | 材料 | value | spread | 锋锐（0.8~2.6）实际范围 |
| --- | --- | --- | --- | --- |
| 1 | 铁 / 金 | 0.50 | 0.40 | 0.49 ~ 1.21 |
| 2 | 铜 | 0.70 | 0.60 | 0.65 ~ 1.73 |
| 3 | 钻石 | 1.00 | 1.00 | 0.80 ~ 2.60 |
| 4 | 下界合金 | 1.30 | 1.25 | 1.09 ~ 3.34 |
| 5 | 星陨 | 1.65 | 1.55 | 1.41 ~ 4.20 |

低档**数值低、波动小**，锻一把是一把，不会大起大落；高档**数值高、波动大**，能出极品也能出平庸货。相邻档位的区间基本不重叠，所以「换材料」永远比「刷同一档」划算。

系数在 `config.yml` 的 `affix-scaling.tiers` 里，`enabled: false` 可退回全档统一。

### 7. 难度曲线（v2.3）

基础节奏整个调快了一档，而且**档位越高越难**：低档适合练手，星陨是硬门槛。

| 工序 | 基准 | 每高一档 | 星陨（tier 5） |
| --- | --- | --- | --- |
| 锻打指针 | 0.1 秒/格 | +12% 速度 | 约 0.06 秒/格 |
| 炉温下降 | 1.5°/秒 | +14% | 约 2.2°/秒 |
| 叠钢时限 | 2.5s + 0.7s×层数 | −11% | 约为基准的 67% |
| 开刃漂移 | 2.9 | +16% | 约 ×1.64 |
| 开刃绿区 | 6~10 | −9% | 约为基准的 64% |
| 抛光指针 | 2.6 点/tick | +16% 速度 | 约 4.6 点/tick（v2.19） |
| 抛光亮区 | 半宽 16 | −9% | 约为基准的 64%（v2.19） |
| 嵌丝亮窗 | 14 tick | −10% | 约为基准的 60%，且根数随档位 +1（v2.19） |
| 总分 | ×1.0 | −1.5% | ×0.94 |

另外**加热窗口内不再保送满分**：原来只要卡进容差就是 95 分以上，现在按偏差平方衰减，只有正中最佳温度才接近 100，压线进窗只有 78 分左右。

这些都在 `config.yml` 的 `difficulty` 段里，觉得太狠就整体调小（比如 `hammer-speed-per-tier: 0.06`），觉得太软就调大。

### 8. 铁砧演出（v2.3）

锻造时会在砧上摆一把剑和一把锤子，落锤有火星、淬火有白汽。全部用 Display 实体实现，不放置真实方块。

**先说清楚一个硬限制**：容器 GUI 打开后，鼠标被界面捕获、视角转不了，而且 GUI 盖住屏幕中间跟下半部分。所以「锻造过程中一边看 GUI 一边看世界动画」在原版机制下做不到。演出的可见性靠三处配合：

1. **开场先演再开界面**：开工时先在砧上摆剑 + 火星 + 一声闷响，`stage-intro-ticks`（默认 14 tick ≈ 0.7 秒）之后才打开加热界面。这段是玩家真正能看清 3D 演出的窗口。
2. **敲击反馈搬进 GUI**：每次落锤，界面正中间的槽位会跳出 `当！`（完美）/ `当！`（良好）/ `哐……`（失手），4 tick 后恢复。这个 100% 看得见。
3. **舞台抬高**：砧面上的演出整体上抬 `stage-height-offset`（默认 1.4 格），剑放大 1.25 倍，实体生成时朝向玩家；找不到真铁砧时替身舞台放在视线前方 `stage-front-distance`（2.5 格）再高出视线 `stage-lift-above-eye`（1.1 格）。

配置：

```yaml
settings:
  anvil-animation: true
  stage-intro-ticks: 14        # 开场演出时长，0 = 立刻开界面
  stage-height-offset: 1.4     # 真铁砧时演出抬高多少
  stage-front-distance: 2.5    # 无铁砧时替身放多远
  stage-lift-above-eye: 1.1    # 无铁砧时替身比视线高多少
```

### 9. 锻造等级（强化）（v2.16 重写：铁砧上敲）

**强化不再是点按钮、不再有界面。** 整条流程照 Steam 上 Forge Tax 那种手感重做：剑放砧子上，拿重锤一下一下敲，砧子上方浮着一块全息，随时告诉你「现在几级、这一锤多大概率成、多大概率碎」。

三步，全部在方块上完成：

```
① 主手拿锻造品 → 右键铁砧      剑放上去，手上那把收走
② 手持重锤     → 左键铁砧      落一锤（扣材料 + 剑币，按明牌概率结算）
③ 空手         → 右键铁砧      把剑取回来
```

重锤不是消耗品：`/zhujian hammer` 领一把（ID 标记在 PDC 上）。默认发的是**铁斧**改的「铁匠重锤」——原版重锤（MACE）要打过试炼密室才拿得到，当强化工具门槛太高。`anvil-forge.hammer.items` 里的材质（默认铁斧 / 重锤 / 石斧 / 铁镐）只要 `allow-vanilla: true` 就直接认，手里有把斧子就能开敲。

#### 砧上的全息

剑一放上去，砧子上方就浮起剑的模型和一块文本：

```
锻造等级 +12/ +99
成功率 74% · 碎裂率 6%
连击 3/5
重锤左键落锤 · 右键取剑
```

- **成功率**：`anvil-forge.success.start` 线性降到 `floor`，默认 **90% → 10%**。跟旧版「前两级必成」不同，+0 也不算必成，但 90% 基本闭眼过。
- **碎裂率**：显示的是**整体碎裂率**（失败率 × 失败后再碎的概率），不是条件概率——看到多少就是多少，不会出现「写 2% 实际连着碎三次」的观感落差。
- **连击**：见下。

#### 连击 → 无损连击强化

连续成功（含大成）累加连击，失败清零。满 `anvil-forge.combo.no-loss-threshold`（默认 **5**）之后，**下一锤是无损连击强化**：

| 项 | 普通一锤 | 无损连击 |
| --- | --- | --- |
| 碎裂 | 有 | **0** |
| 掉级 | 有（损伤） | **不掉了** |
| 结果 | +1 / +2 / 掉 1 / 空锤 / 碎 | **必成**，`+1` 或大成 `+2` |
| 连击 | +1 | 打出去后**归零** |

全息上会直接写「下一锤：无损连击强化（必成 · 不碎）」。这是长线爬 +99 唯一稳的台阶——不是保底符那种「死后复活」，是攒够了给你一次确定的推进。

#### 五态明牌

每一锤在这五态里掷一次，概率全部明牌展示，**五项相加恒为 1**：

| 态 | 结果 |
| --- | --- |
| 碎裂 | 剑胚消失（护胚符可顶成「损伤」） |
| 损伤 | 掉 1 级，连击清零 |
| 空锤 | 等级不动，连击清零，材料和钱照扣 |
| 大成 | **+2 级** |
| 成功 | +1 级 |

```yaml
anvil-forge:
  tickets:            # 实际键名在 strengthen.tickets
    great-base: 0.08       # 大成基础概率
    great-per-combo: 0.03  # 连击每点 +3% 大成
    damage-share: 0.5      # 失败里「损伤 : 空锤」= 1:1
```

#### 强化上限跟着锻造品质逐级提高（v2.17）

v2.16 是「所有物品统一 +99」，粗糙剑和神话剑能锤到一样高，品质在强化这条线上没意义。v2.17 改回按**锻造品质**分档，六个品质严格递增：

| 品质 | 上限 | 备注 |
| --- | --- | --- |
| 粗糙 ROUGH | +40 | 开局货，够用但不耐久锤 |
| 普通 COMMON | +50 | 铁系主力 |
| 精良 FINE | +60 | |
| 史诗 EPIC | +72 | |
| 传说 LEGENDARY | +86 | |
| 神话 MYTHIC | +99 | 封顶，一整套下来要锤掉上千个材料 |

```yaml
anvil-forge:
  max-level: 99        # 只剩两个用处：没有品质键的老物品兜底 + 成功率/碎裂率曲线的分母
  caps:
    ROUGH: 40
    COMMON: 50
    FINE: 60
    EPIC: 72
    LEGENDARY: 86
    MYTHIC: 99
```

三条要点：

- **品质上限 ≠ 现在能锤到哪**。中途还有 6 道蜕变门槛（+5 / +10 / +15 / +20 / +25 / +30），撞到门槛必须先 `/zhujian evolve`。砧上的全息会写清楚：没到门槛时是 `本阶门槛 +5`，到了是 `本阶已满 +5 · 先蜕变「精钢」才解锁 +6 以上`。
- **材料档位不再影响上限**，只影响「锤一次多贵」（`cost.tier-factor`、`material.tier-factor`）。
- **老物品自动迁移**：v2.17 之前铸出来的东西 PDC 里冻着按材料档位算的旧上限（神话剑一出生写的就是 `+0/32`）。`StrengthenService.ensureCap()` 会在三个时机把它同步成品质上限——玩家登录扫背包、`/zhujian strengthen`、把剑放上铁砧；等级超过新上限的会被夹回上限，Lore 一起重写。`strengthen.caps` 只在 `anvil-forge.enabled: false` 时才生效。

#### 消耗

```
每锤剑币 = (cost.base + cost.per-level × 当前等级) × cost.tier-factor^(档位-1)
每锤材料 = ceil(material.base × material.tier-factor^(档位-1))          # 固定，不随等级涨
```

默认 `40 / 6 / 1.20` 与 `2 / 1.20`。铁剑从 +0 敲到 +20 累计约 **2.1k 剑币**（旧曲线 7.5k），每锤固定吃 2 个铁锭——单锤便宜、次数多，节奏更像「一直敲」而不是「攒够钱点一下」。

材料是**这把剑自己的锻造材料**：铁剑吃铁锭，星陨剑吃星陨锭。

#### 护胚符 / 炉火 / 传承

这三样原样保留：

- **护胚符**（`strengthen.talisman`，默认 ECHO_SHARD）：碎裂判定命中时自动顶一次，把「碎」换成「掉 1 级」。放背包就行，不用手持。
- **炉火保底**（`strengthen.furnace`）：每失败一次攒 1 点，攒满下一锤必成——和「无损连击」是两条独立的路，都指向同一个方向：赌久了总得给你一次确定的。
- **剑魂传承**（`strengthen.inherit`）：+N 的剑碎了，下一把新铸的带 `floor(N × rate)` 级。

#### 不丢剑

砧位状态落盘到 `plugins/ForgingMaster/anvils.yml`（world / x / y / z / owner / 放上去的时间 / **完整 ItemStack**）。所以：

- 关服、重载、崩服 → 起来后原样恢复，全息会补回来（实体是 `setPersistent(false)`，靠区块加载事件重生）。
- 铁砧被拆 / 被炸 → 剑还给主人；人不在线就掉在砧子旁边，**不吞**。
- `anvil-forge.session-timeout-minutes`（默认 0 = 不超时）可以设超时，到点自动还剑。

#### 手感细节

- 两锤之间有 `strike-cooldown-ms`（默认 450ms，v2.17.3 起代码兜底与配置对齐）冷却，防连点刷屏，不卡手速。
- 每次落锤都有声音：成功 `BLOCK_ANVIL_USE` 升调、大成接 `ENTITY_PLAYER_LEVELUP`、碎裂 `ENTITY_ITEM_BREAK` 压低、空锤/损伤 `BLOCK_ANVIL_LAND`。
- 别人放剑的砧位你碰不了（`owner-only: true`），只会被告知「这是 XXX 的砧位」。
- 普通铁砧照常能用——手上不是锻造品、不是重锤、砧上也没剑时，插件完全不插手原版修理。

#### 完整配置

```yaml
anvil-forge:
  enabled: true
  max-level: 99               # 曲线分母 + 无品质键的老物品兜底（上限看下面的 caps）
  caps:                       # v2.17：强化上限按锻造品质逐级提高
    ROUGH: 40
    COMMON: 50
    FINE: 60
    EPIC: 72
    LEGENDARY: 86
    MYTHIC: 99
  owner-only: true
  strike-cooldown-ms: 300
  session-timeout-minutes: 0  # 0 = 不超时
  hammer:
    item: MACE
    allow-vanilla: true
  success:
    start: 0.90               # +0 的成功率
    floor: 0.10               # +99 的成功率
  break:
    base: 0.02                # 失败后再碎的几率（+0）
    max: 0.30                 # 失败后再碎的几率（+99）
  combo:
    no-loss-threshold: 5      # 攒到 5 连 → 下一锤无损（0 = 关闭）
    success-bonus-per: 0.03   # 连击每点 +3% 成功率
    success-bonus-max: 0.15
    break-shield: 4           # 连击 ≥4：碎裂转损伤（每把剑一次）
  cost:
    base: 40
    per-level: 6
    tier-factor: 1.20
  material:
    base: 2                   # 固定每锤几个
    tier-factor: 1.20
  display:
    height: 1.35              # 全息离砧面多高
    sword-transform: NONE     # 剑的姿态：NONE = 自己算角度（平躺，默认）/ GROUND = 原版掉落物姿态 / FIXED = 立着
    sword-height: 1.03        # 剑心离方块底面多高：砧面在 y+1.0，1.03 恰好贴面不穿模
    sword-yaw: 90             # 剑在砧面上的朝向（90 = 横着躺）
    sword-pitch: -90          # NONE 下 -90 = 把立着的模型扳倒成平躺
    sword-scale: 0.95         # 剑的大小：NONE 没有原版那层 0.5 缩放，0.95 铺满砧面不出边
    sword-scale-max: 1.30     # 锻到上限 +99 时的大小（越锻越厚实）
  animation:
    enabled: true             # 落锤演出：一把重锤竖着砸下来
    duration-ticks: 12        # 整段演出几 tick
    impact-tick: 7            # 第几 tick 砸中（之后是反震与抽走）
    hammer-item: MACE         # 演出里那把锤子：MACE = 原版重锤，锤头朝下
    hammer-scale: 1.10        # 演出锤子大小
    billboard: CENTER         # CENTER = 永远面向玩家（任何角度都看得见整把锤子）
    # ---- v2.17.2 起动作改成「柄底不动、锤头绕柄砸下」----
    # roll-deg / windup-deg / start-height / hit-height 四个键已废弃（代码不再读取）
    pivot-height: 2.10        # 柄底（手的位置）：砧面上方 1.10 格，锤头全长 ~1.05，太低会砸进砧子
    handle-length: 0.46       # 柄底到模型中心长度，决定画弧半径
    swing-start-deg: -25      # 起手角度：负数 = 锤头向后扬起（0 = 朝上）
    swing-hit-deg: 170        # 砸中角度：锤头几乎转到正下方，落在剑面上
    swing-rebound-deg: 12     # 砸中后被砧面顶回多少度
  spark:
    enabled: true
    count: 18                 # 每次落锤迸多少颗火花
    spread: 0.35              # 迸溅半径
```

剑是**真的平躺在砧面上**：`ItemDisplay` 用 `NONE` 姿态 + 我们自己算的四元数（先绕 X 扳倒 90°，再绕 Y 转到朝向）。v2.16.1 之前用的是原版 `GROUND` 姿态，那套会先把模型缩到 0.5、再往下沉 2/16 格，看着不像躺在砧面上，倒像插进砧子里。老配置会在开服时自动迁移（补 `sword-transform: NONE`、`sword-pitch: -90`、`sword-scale: 0.95`、`sword-height: 1.03`，并把过期的注释换掉，写 `pose-version: 2`；v2.16.3 推到 3：演出锤子换成 `MACE`、补 `impact-tick / billboard / roll-deg / windup-deg / start-height / hit-height`；v2.17 推到 4：补 `anvil-forge.caps` 六档品质上限；服主改过的值不动）。

#### 炉火保底（v2.5）

纯赌会把人劝退，所以加了炉火：**每失败一次攒 1 点，攒满则下一级必成，成功后清零**。

攒满所需的点数按当前等级分档：

```yaml
strengthen:
  furnace:
    need-low: 3      # 等级 ≤ 10
    need-mid: 5      # 等级 ≤ 20
    need-high: 8     # 更高
```

也就是说 +0 撞墙三次必过、+20 附近撞五次必过（`furnaceNeed` 在 ≤20 走 `need-mid: 5`，8 次是更高档 `need-high`）。炉火只在**真失败**时涨（护胚符顶碎、稳胚符保级都算失败，照样涨），碎裂则随剑一起消失。`describe()` 与强化结果里都会显示 `炉火 2/3` 进度，攒满时提示「炉火已满，这一锻必成」。

#### 期望模拟（v2.5）

`/zhujian strengthen sim [目标等级]` 算「从现在锻到目标要付出什么」，**纯模拟，不扣任何东西、不动物品**：

```
/zhujian strengthen sim 20
→ 期望尝试 26.4 次 · 期望消耗 138 个铁锭 · 期望花掉 4.2 万剑币
→ 期望碎剑 1.7 次 · 在碎之前达成目标的概率 61%
```

模型是一维马尔可夫链：等级 L 上锤一次，成功率 p(L)、碎裂率 b(L)，失败没碎时降到 L−1。**因为降级会把已经付过的费用再付一遍，期望次数永远大于 1/p**——它解两个线性方程组（各等级的访问次数、各等级的达成概率）而不是简单相除，用 40 万次蒙特卡洛交叉验证过 6 组参数，误差 < 0.2%。调数值之前先跑一遍这个，比自己心算靠谱。

#### 强化履历（v2.5）

Lore 里「锻造等级」正下方会多一行履历，只有真失败过才出现：

```
锻造等级: +7/+20 (基础属性 +14%)
履历: 失败 3 次 · 碎剑 1 次 · 投入 47 个铁锭
```

三个计数写进 PDC（`strengthen_fails` / `strengthen_broken` / `strengthen_invest`），跟着物品走、反复强化只保留一行。碎剑留档的条目也会带上这些数字。

#### 三符（v2.5）

护胚符扩成三兄弟，放背包里自动生效，**各自独立消耗、可同时叠加**：

| 符 | 作用 | 触发时机 | 默认价 |
| --- | --- | --- | --- |
| 护胚符 | 碎裂判定命中时顶一次，把「碎」换成「降 1 级」 | 失败且本该碎 | 1500 |
| 稳胚符 | 失败不掉级 | 失败且本来会掉级 | 2000 |
| 旺火符 | 本次成功率 **+15 个百分点** | 开锻就烧掉 | 2500 |

护胚 + 稳胚可以叠：护胚把「碎」换成「掉 1 级」，稳胚再把这 1 级托住，两符各扣一张，结果是不碎也不掉。旺火符在**本来就必成**（炉火满）时不消耗，不会白烧。

#### 碎剑进剑冢（v2.5）

剑胚碎掉不再凭空消失：`destroy()` 会先把残骸写进剑冢留档（锻造者、碎在 +几、材料、品质、评分、快照），再把它从**砧位上**撤掉（v2.16 起剑已不在背包里，走 `onBroken` 回调清砧位；老的命令路径仍然从主手摘），并把剑冢编号回显给玩家。

留档条目有两个特殊规则：**不能 `take()` 取回**（已经是废铁了），也**不占 `tomb.max-per-player` 埋剑名额**。剑冢列表里标「碎剑留档 · 碎在 +N」。`strengthen.fail.tomb-record: false` 可以整个关掉。

### 10. 词条重铸（v2.5）

锻出来的词条是随机的，抽到「耐久 + 击退」而想要「锋利 + 吸血」时，以前只能重锻一把整剑。现在可以只换其中一条：

```
/zhujian strengthen reforge        # 列出这件所有的词条，带预览
/zhujian strengthen reforge 2      # 重铸第 2 条
```

规则：

- **铁律是不重复**：抽取阶段就把「本条之外已存在的 id」排除掉，同 id 物理上不可能出现两次。池子按武器 / 装备分开（武器走淬火介质，装备走 `reforge.armor-pool`）。
- **位置保留**：只覆盖这一条，Lore 顺序与 PDC 顺序都不动。
- **属性精确替换**：按 `fm_<词条id>` 键名精确删旧写新；`fm_atk` / `fm_speed` / `fm_armor` / `fm_toughness` 有双向护栏，绝不误删基础属性。
- **自定义词条走差量**：暴击率、偷血这类聚合在 PDC 上的词条只做「减旧值加新值」，不整表重算——否则会抹掉宝石与剑灵已经累加的份额。
- **Lore 自己重画**：整块摘下再按新列表重画，顺手清掉历史重复块与「（无词条」占位行。

费用：

```yaml
reforge:
  enabled: true
  consume-materials: false   # true = 除了剑币还吃对应锻造材料
  cost:
    base: 320                # 第 1 条
    per-index: 180           # 每往后一条再加
    tier-factor: 1.75        # 每高一档 ×
  material:
    base: 2
    per-index: 1
    tier-factor: 1.15
```

### 11. 竞技分级（v2.5）

`/zhujian duel` 以前不分等级，+32 星陨剑打 +5 铁剑是屠杀。现在按主手武器的锻造等级分档，默认三档：**0-9 / 10-19 / 20+**。

```yaml
duel:
  strengthen-tier:
    enabled: true        # false = 回到无差别竞技
    bounds: [10, 20]     # 档位边界
    allow-cross: false   # 允许跨档开打；false 时直接拒绝
    balance: true        # 跨档时把高等级方临时压到低等级方
```

跨档被拒时会提示「对方档位 20+，你是 0-9」。开着 `allow-cross` 时可以把高等级方的强化加成**临时**压到低等级那一档：

- 实现方式是给玩家挂 `ATTACK_DAMAGE` / `ATTACK_SPEED` 的负 `ADD_NUMBER` 修正，**不碰物品 NBT**，用 `addTransientModifier` 所以不进存档；
- 清理点覆盖六条路径：正常结算、玩家退出、对局中断、应战失败、应战时档位不符、关服/停用插件，每条都幂等；
- 防绕过：应战时取「发起时」与「应战时」等级的较大值，临时换低级剑降不了档。

### 12. 剑意 · 武器熟练度（v2.6）

数值会骗人，用得久不会。每用这把锻造品击杀一个生物攒 **1 点剑意**，跨档给固定百分比攻击加成：

| 档 | 剑意 | 称号 | 攻击加成 |
| --- | --- | --- | --- |
| 0 | 0 | 生涩 | — |
| 1 | 100 | 顺手 | +2% |
| 2 | 500 | 趁手 | +4% |
| 3 | 2000 | 心意相通 | +7% |
| 4 | 5000 | 剑即是我 | +10% |

Lore 里长这样：

```
锻造等级: +5/+20 (基础属性 +10%)
剑意: 趁手 · 1247/2000 (+4% 攻击)
```

**分子是当前档的门槛，括号里是当前档的加成**——1247 在「趁手」档（500~1999），所以显示 4%。

**加成是独立一层**：走 `ADD_SCALAR`，原版结算顺序是 `ADD_NUMBER → ADD_SCALAR → MULTIPLY_SCALAR_1`，所以剑意天然叠在「强化放大之后」，是乘算百分比。它不碰 `fm_atk / fm_speed / fm_armor / fm_toughness` 这些基础属性键，也不碰词条键。

不统计 PVP 击杀（防互刷），`proficiency.pvp: true` 可开。剑意值写在物品 PDC 里跟着剑走，玩家死亡时保底回写防丢，**不扣分**——扣分太劝退。

```yaml
proficiency:
  enabled: true
  lore: true
  tiers: [100, 500, 2000, 5000]
  tier-names: ["生涩", "顺手", "趁手", "心意相通", "剑即是我"]
  bonuses: [0.02, 0.04, 0.07, 0.10]
  pvp: false
  broadcast-min-tier: 0     # 设 3 则「心意相通」起全服播报
```

### 13. 赛季追赶（v2.6）

赛季后期有个死结：老玩家早在 +20 卡着，新人在同一个成功率下永远追不上，只能等下赛季重置。所以加了追赶——**赛季越往后，低等级段越容易成功**：

```
追赶加成 = min(max-bonus, 本季已过天数 × per-day)
        再夹到 (1 − 基础成功率) × 0.9
successChance(L) = min(1.0, baseSuccessChance(L) + 追赶加成)     // 仅 L ≤ level-threshold
```

默认参数跑满一个 30 天赛季，赛季末的效果：

| 等级 | 无追赶 | 赛季末 | 说明 |
| --- | --- | --- | --- |
| +0 ~ +2 | 100% | 100% | 本来就必成，不吃追赶 |
| +3 | 97.5% | 99.75% | 差一点点，但**仍然不是必成** |
| +5 | 90.5% | 99.05% | |
| +10 | 73% | 97.3% | |
| +12 | 66% | 91% | 阈值内最后一档，吃满 +25 |
| +13 | 62.5% | 62.5% | 阈值外，一点不涨 |
| +20 | 38% | 38% | |

三点设计取舍：

- **必成只留给炉火和旺火符**。加成额外夹了「剩余空间的 90%」，所以 +3 在赛季末是 99.75% 而不是 100%——否则「必成」这个词就没有意义了。
- **赛季结算瞬间断崖归零**，不做渐变。渐变会拖到下赛季初，和新老玩家重新起跑的设计冲突。
- **同一次锻造内只读一次加成**，不会出现「按 A 概率收钱、按 B 概率结算」。

```yaml
strengthen:
  season-catchup:
    enabled: true
    max-bonus: 0.25           # 赛季末最多抬 25 个百分点
    level-threshold: 12       # 只帮 +12 及以下
    per-day: 0.01             # 每过一天抬 1 个百分点
```

`/zhujian strengthen info` 和 `sim` 里都会标注这次吃了多少追赶，玩家能看见。

### 14. 词条重铸界面（v2.6）

之前只有命令，现在主菜单第 13 格有入口（铁匠台图标），也可以 `/zhujian strengthen reforge gui` 直接打开。

- 一条词条一个按钮，显示当前数值、本档可能范围、价格

### 15. 剑冢残影挑战（v2.7）

以前剑冢是纯陈列：埋进去的剑躺着，只能看和取回。现在能打。

`/zhujian tomb challenge <编号>` 召唤原剑主人的残影——按那把剑的强化等级和品质缩放：

| 档位 | 材料 | 残影 |
| --- | --- | --- |
| 1 | 铁 / 金 | 僵尸 |
| 2 | 铜 | 尸壳 |
| 3 | 钻石 | 凋灵骷髅 |
| 4 | 下界合金 | 猪灵蛮兵 |
| 5 | 星陨 | 监守者（`.mobs.starfall` 可换成温和的） |

```
血量 = 生物基础血量 × (1 + 强化等级 × 0.08) × 品质系数      // 上限 300
攻击 = (6.0 + 原剑基础攻击) × (1 + 强化等级 × 0.08) × 品质系数 × 0.55   // 上限 40
```

品质系数沿用 `Quality.power()`：ROUGH 0.55 / COMMON 0.80 / FINE 1.00 / EPIC 1.22 / LEGENDARY 1.45 / MYTHIC 1.75。

**打赢**：按 `clamp(0.40 + 强化等级 × 0.02, 0, 0.60)` 返还材料（每种耗材分别取整，全为 0 时保底 1 个），15% 概率额外给护胚符或随机宝石（各占一半）。全服播报。

**打输 / 超时**：无惩罚，可以再战。冷却默认只在打赢时写入，`cooldown-on-loss: true` 可改。

实现上几个必要的细节：
- 残影带记分板 tag，**回收只认 tag**，不会误删玩家的宠物
- `setPersistent(true)` + `setRemoveWhenFarAway(false)`，不会自然消失
- 死亡时 `drops.clear()` + `setDroppedExp(0)`，不给原版战利品
- 主手装备是同材质的普通剑 + 名字，掉落概率 0
- 玩家离线 / 死亡 / 跑出 40 格（`tomb.challenge.leave-radius`）持续 60 秒 → 回收
- 开服时延迟 1 秒清一次上回崩服留下的孤儿残影

```yaml
tomb:
  challenge:
    enabled: true
    cooldown-hours: 24       # 同一条记录每人每天一次（0 = 不限）
    cooldown-on-loss: false  # 打输也进冷却
    consume: false           # 打赢后销毁记录
    max-health: 300
    max-attack: 40
    reward:
      rate-base: 0.40
      rate-per-level: 0.02
      rate-max: 0.60
      bonus-chance: 0.15
```

> **一处行为变更**：剑冢界面左键现在也召唤残影（以前是「配方复刻掷骰」）。旧玩法以 `TombManager.recipeChallenge(...)` 保留，逻辑一行没改，只是不再挂命令和界面。

### 16. 词条套装（v2.7）

词条以前是各自独立的加法，现在集齐特定组合触发隐藏效果：

| 套装 | 需要的词条 | 效果 |
| --- | --- | --- |
| 饮血 | 锋锐 + 饮血 + 破绽 | 命中回复 8% 伤害，额外 +5% 攻击 |
| 铁壁 | 厚甲 + 坚壁 + 庇护 | 受到伤害减少 6%，额外 +2% 攻击 |
| 断罪 | 锋锐 + 致命 + 轻捷 | 目标血量低于 30% 时伤害 +15% |
| 淬毒 | 燃烬 + 破绽 + 饮血 | 命中附加 3 秒缓慢 |

Lore 里多一行 `套装: 饮血 · 命中回复 8% 伤害`；只差一条时显示灰色 `套装: 饮血 2/3`——**套装玩法的动力就来自「差那一条」**，不显示进度的话玩家永远不知道离触发多远。

属性加成走 `ADD_SCALAR`，键名 `fm_set_<套装id>`，和基础属性、剑意的 `fm_prof_atk` 完全隔离。所以结算层级是稳的：

```
基础 + 强化 + 词条  →  × 套装  →  × 剑意
```

**配装难度是真的**：一件物品的持词条数 = 品质（ROUGH 0 / COMMON 1 / FINE 2 / **EPIC 3** / LEGENDARY 4 / MYTHIC 5），三词条套装至少 EPIC 才可能，主要靠重铸逐条凑。护甲池只有 5 条，铁壁要求 3 条全中 = EPIC 护甲 1/10 概率，最需要重铸。饮血与淬毒共享 `饮血 + 破绽`，四词条武器可以同时吃两套。

伤害监听的优先级是 `NORMAL`，`CombatListener`（HIGH，暴击倍率）和 `ForgeListener.onDamaged`（HIGH，护甲减伤）都在它之后跑，读的是**当前** damage，所以是乘法叠加、互不覆盖。同一套装在多件装备上满足时减伤取最大只算一次，不会叠成免伤。

```yaml
affix-set:
  enabled: true
  lore: true
  progress: true             # 差一条时显示灰色进度
```

### 17. 锻造大赛实时观战（v2.7）

以前大赛只有「开始 / 结束 / 看榜」，里面发生了什么外面完全看不到。

`/zhujian contest watch` 打开实时面板：

- 每个参赛者一行：名字、当前阶段（加热 / 锻打 / 叠钢 / 开刃 / **抛光** / **嵌银丝** / 淬火 / 已完成）、分数、名次（v2.19 起观战标签跟上两道收尾工序，图标分别是纸与线）
- 已交剑的显示成品品质，自己那行标 `◀ 这是你`
- 顶部：剩余时间（带进度条）、剑胚、领先者、参赛人数（交剑 · 在打 · 合计）

**刷新不闪**：每个观察者一个 `BukkitTask`（默认 20 tick = 1 秒），每格算「材质 + 标题 + lore」签名，和上一帧一样就跳过，连 ItemStack 都不新建。只重画变化的格子，不重建 Inventory，标题也不动。

**不泄漏**：界面关闭（只认登记的那一份，防止「关掉又立刻重开」时旧 close 事件掐死新任务）、玩家退出、界面被换、大赛结束（定格成「本场已结束」再停表）、`shutdown()` —— 五条路都会 cancel 并清表。tick 内包 try/catch，画崩即收摊。

**参赛者能看自己**：面板只读、不参与评分，选手更需要全局态势判断差距。唯一的拦截是技术性的——锻造界面开着时打开观战会触发 `InventoryCloseEvent` → `ForgeManager.onInventoryClosed()` → `cancel()`，材料和费都不退，所以会提示「先收尾这一炉」。

```yaml
contest:
  watch:
    rows: 6
    refresh-ticks: 20
    show-left: true
```

### 18. 赛季剑传承（v2.7）

赛季一重置，强化进度归零，攒了一整个赛季的剑就变成普通数字。给它一个留名的出口。

赛季结算时自动选出全服最强的一把剑，刻进 `hall-legacy.yml`（只增不删），名人堂多一排「历代名剑」。

**复合分**：

```
复合分 = 品质序号 × 1000 + 锻造评分 × 1 + 强化等级 × 50
```

权重是刻意这么定的：

- **品质 ×1000**：一档品质压得住「评分满值 + 强化大半」
- **评分 ×1**：本身 0~100，原样吃进来，不跟别的维度抢量级
- **强化 ×50**：满强化（现行品质上限 +40 ~ +99）值 2000~4950。语义是**低一档胚子捶到底 = 高一档胚子裸奔**（`compositeRaw(1,35,0) == compositeRaw(0,35,20) == 1035`）。不这么做，赛季末就只剩比胚子，强化系统的整个赛季投入白费

**候选只读 `StatsStore`**，不碰在线背包 —— 凌晨无人时结算也得跑得通。过滤掉自检数据与空档案，四段排序（复合分 → 评分 → 强化 → UUID）保证并列时结果确定。

**材料还原**有两道线索：先看「强化之巅」那条纪录的锻造者是不是同一个人（借它的材料），否则翻图鉴按同品质、id 字典序取第一个——`StatsStore` 压根没存材料。

陈列用**盔甲架而不是告示牌**：告示牌要在世界里落方块，摆放和清理都要改档还原，玩家动一格就可能被拆。盔甲架是实体，靠 PDC 精确回收，三类共用 `clearAll()`，rank 标记分区间（名次 `1..N` / 强化 `-1` / 名剑 `-1000-i`）杜绝串号。

```yaml
season:
  legacy:
    enabled: true
    broadcast: true
    show-row: true
    show-count: 5
    weight:
      quality: 1000.0
      score: 1.0
      strengthen: 50.0
```

`/zhujian top legacy` 列出历代名剑。

### 19. 名人堂与排行榜：强化维度（v2.5）

名人堂多一条「最高锻造等级」，只保留历史最高，打平不覆盖（除非达成时间更早）。存档单独放 `hall-strengthen.yml`——故意不塞进 `hall.yml`，那份会被 `/zhujian halloffame set` 整份重写。陈列里会在 Top 榜下方多摆一排「强化之巅」。

排行榜多一个「强化」维度，读的是**历史最高等级**——强化成功时落库到 `StatsStore`（字段 `best-strengthen`），**只涨不跌**：

- 强化失败掉级，历史最高不回退。榜上看的是「这把剑曾经锻到过哪儿」，不是此刻在哪儿。
- 人不在线也照样有名次，剑放箱子/末影箱里也不丢。
- 老玩家第一次上线时会自动补录：扫到背包里 +N 就写进档案，不用重新强化一遍。

在线背包扫描仍然保留，作用有两个：拿到物品名和材料名（落库只记等级），以及补录历史遗留数据。两者按**取较大值**合并，`rank.strengthen.snapshot-seconds` 控制缓存秒数。

强化成功时会自动写入名人堂（`StrengthenService` 成功分支里 `record()`），低等级有 `min-level` 兜底不会占位。

### 20. 词条符：剥下来，装到别处（v2.8）

重铸解决「这条不想要」，词条符解决「这条不想浪费」。一把锤到 +20 的剑上有一条好词条，
换胚子时以前只能连词条一起扔；现在能把它剥成一张可交易、可存箱的符。

```
/zhujian strengthen strip 2      # 把主手第 2 条词条剥成词条符
/zhujian strengthen graft        # 主手锻造品 + 副手词条符 → 把词条装进去
```

规则：

- **数值原样搬运**：符里存的是剥离那一刻的实际值，不回滚、不重抽。否则「剥下来再装回去」就是洗数值。
- **同 id 不重复**：目标剑上已经有同一条词条时直接拒绝，跟重铸的抽取规则一致。
- **武器 / 装备分池**：武器词条只能进武器，装备词条只能进护甲（符上记 `imprint_armor`）。
- **上限 6 条**：`imprint.max-affixes`，与锻造「七工序满分 +1、专精 +1」的天花板一致。
- **属性一起搬家**：属性词条走 `fm_<id>` modifier 精确摘除 / 重写，暴击、吸血、点燃、减伤走 PDC 差量，
  **宝石与剑灵累加的那部分不会被抹掉**；Lore 词条块整块重画，套装行也跟着重刷
  （剥掉一条正好散掉套装、装上去正好凑齐，都会立刻反映）。
- **失败不扣费**：读不到词条数值、配置里已经没有这条词条、词条满了、池别不对——一律先拒后扣。

费用（剑币，与强化、重铸同一套内置货币）：

```
剥离 = (260 + 120 × 序号) × 1.5^(档位-1)
移植 = 480 × 1.6^(档位-1)
```

铁剑剥第一条 260、移植 480；星陨剥第一条 585、移植 1228。剥到一条不剩时 Lore 显示
`（无词条 · 火候和锤法还不够）`，不会留一个空标题。

```yaml
imprint:
  enabled: true
  max-affixes: 6
  strip:
    cost-base: 260
    cost-per-index: 120
    tier-factor: 1.5
  graft:
    cost-base: 480
    tier-factor: 1.6
```

> **为什么允许「低档胚子刷词条再剥出来喂高档剑」**：低档词条的数值本来就低（见 6.1 的分档），
> 剥一次还要付手续费，算下来不如直接锻一把高档的。要收紧就调 `imprint.strip.cost-base`。
