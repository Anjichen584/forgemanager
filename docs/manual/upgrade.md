## 十四、升级指南（1.x → 2.0）

### 1. 升级前
1. **备份整个 `plugins/ForgingMaster/` 目录**（或在旧版本里执行 `/zhujian backup`）。
2. 停服，替换 jar 为 2.0 版本。

### 2. config.yml
- 2.0 **不会覆盖**已有的 `config.yml`，因此新增段需要你手动补：`coins`、`mentor`、`environment`、`shop`、`risk`、`events`、`spirit`、`tomb`、`hall-of-fame`、`achievements`、`craft-rank`、`auction`，以及 `rank`、`season`（如果你的 1.x 配置里没有）。
- 最省事的做法：备份旧 `config.yml` 后删除它，重启让插件生成完整的带注释版本，再把旧的数值手动抄回去。
- 启动时控制台会列出缺少的键（只针对部分关键键），缺少的键会使用内置默认值，不影响启动，但功能参数会按默认值走。

### 3. data.yml
- 新字段（剑币、连锻、师徒、成就、段位、剑灵、剑冢、风险统计等）**读取时自动补默认值**，老档案无需迁移。
- 老玩家的剑币从 0 开始，师徒关系默认为空。

### 4. 赛季文件
- 首次启动时，赛季编号取 `season.number`，之后以 `season.yml` 为准。
- 老服没有 `season.yml` 也没关系，会自动创建。
- 第一次结算后会在 `seasons/` 下生成归档文件，之前的赛季不会有归档（1.x 没有赛季）。

### 5. 备份与回档
- `/zhujian backup` 的备份只包含上表列出的存档文件。
- `/zhujian restore <id>` 回档后，**需要重启服务器**才能让内存数据生效，否则运行中的服务器可能把旧数据再写回。

### 6. 2.0 → 2.1
- `config.yml` 新增 `economy`、`armor` 两段，以及 `materials.*.price`、`materials.*.costs`。
- 旧配置不会自动补这些键，**建议备份后删除 `config.yml` 让插件重新生成**，再把自定义数值抄回去。
- 不补也能启动：没有 `price` 就不收锻造费，没有 `armor` 段则装备入口默认开启、价格系数按 1.0。
- 旧锻造品（2.0 产出的）不受影响；装备是新物品类型，老数据里不存在。

### 7. 2.1 → 2.2
- `config.yml` 新增 `gems` 段与 `materials.*.base-durability`。
- **耐久算法变了**：老成品存的是旧的 `durability_max`（80 + 品质×40），不会自动重算，继续按旧值用；新锻的才吃新公式。想让老物件也吃新数值的话，需要手动重置耐久（暂无命令，后续可加）。
- 宝石物品与孔位都是新 PDC 数据，老物品默认 0 孔，用 `/zhujian gem socket` 开就行。

### 8. 2.2 → 2.4

**老武器能不能继承？能，原样继承，而且比新锻的还强一点。**

| 老物品身上的东西 | 2.4 之后的表现 |
| --- | --- |
| 基础攻击 / 攻速 / 护甲 / 韧性 | **不变**。属性是写在物品组件里的历史值，插件不主动重算，砍 30% 只影响**新锻出来的**成品 |
| 词条数值 | **不变**。词条值当年就已经落进 modifier 与 PDC，不会按新的分档重抽 |
| 宝石、孔位、耐久、钢纹、剑灵、锻造者 | 全部不变 |
| 锻造等级 | 老物品没有这两个键，读取时**等级按 0、上限按材料档位现算**，可以直接强化，不需要迁移 |

所以升级后会出现：老铁剑基础 1.6（旧配置 2.0×0.8），新铁剑基础 1.12（新配置 1.4×0.8）。老物件更强，属于老玩家留存，不需要额外处理。

要让老物件也吃新数值（主动削弱老玩家资产），需要另写迁移命令逐把重算，风险高，**默认不做**。

其它：

- `config.yml` 新增 `affix-scaling`、`strengthen`、`armor.tiers` 三段，删掉旧的 `armor` 里写死的护甲值。
- 建议备份 `config.yml` 后删掉让它重新生成，再把自定义数值抄回去——否则新段全走内置兜底值。
- 版本号 2.2.0 → 2.4.0（2.3 是难度曲线与铁砧演出，2.4 是词条分档与锻造等级），产物名同步变成 `ForgingMaster-2.4.0.jar`。

### 8.1 2.4 → 2.5

**这一版不动物品数值，全是加法，老东西一件都不用迁移。**

| 改动 | 对老物品的影响 |
| --- | --- |
| 强化加了成功率 / 碎裂 / 炉火 / 三符 | 等级、上限、基础属性快照全不变。老武器照旧强化，只是现在会失败 |
| 强化履历 | 新物品才有；老物品第一次强化后才开始记，之前的历史无从追溯 |
| 碎剑进剑冢 | 只影响以后碎的剑 |
| 词条重铸 | 纯新增命令，不碰已有词条 |
| 竞技分级 | 只影响 `/zhujian duel` 的匹配，不改属性 |
| 名人堂 / 排行加强化维度 | 纯新增展示 |
| 附魔取回 | 纯新增命令 |

新增配置段：`strengthen.{success,fail,material,talisman,furnace,steady,kindle}`、`shop.specials.{steady,charm-kindle}`、`gems.enchant-extract`、`duel.strengthen-tier`、`reforge`、`hall-of-fame.strengthen`、`rank.strengthen`。

升级步骤同 2.2 → 2.4：**备份后删掉 `plugins/ForgingMaster/config.yml` 让它重新生成**，再把自定义数值抄回去。不删也能跑（所有新键都有内置默认值），但启动会 warn 一串缺键。

> 注意：`rank.strengthen` 和 `hall-of-fame.strengthen` 是**子段**，挂在已有的 `rank:` 与 `hall-of-fame:` 顶层键下面。手工加的时候别另起顶层键——YAML 重复键会让后一个整段覆盖前一个。

版本号 2.4.0 → 2.5.0，产物名 `ForgingMaster-2.5.0.jar`。

### 8.2 2.5 → 2.6

**依然不动物品数值，老东西一件都不用迁移。**

| 改动 | 对老物品的影响 |
| --- | --- |
| 剑意（武器熟练度） | 老剑的剑意从 0 起算。它没有历史击杀记录，这是必然的——不可能追溯出「这把剑以前杀过多少」 |
| 赛季追赶 | 纯公式层，不写物品。老剑强化时自动享受当前赛季的追赶加成 |
| 词条重铸界面 | 纯 UI，功能还是原来那个 |
| 强化榜改历史最高 | 老玩家第一次上线自动补录，不用重新强化 |

新增配置段：`proficiency`（10 个键）、`strengthen.season-catchup`（4 个键）、`reforge.confirm-ticks` / `reforge.permission`。

升级步骤同前：**备份后删掉 `plugins/ForgingMaster/config.yml` 让它重新生成**。不删也能跑（全部有内置默认值），但启动会 warn 一串缺键。

版本号 2.5.0 → 2.6.0，产物名 `ForgingMaster-2.6.0.jar`。

### 8.3 2.7 → 2.8

**不动物品数值，老东西一件都不用迁移。**

| 改动 | 对老物品的影响 |
| --- | --- |
| 词条符（剥离 / 移植） | 纯新增命令，词条只有你主动剥才会动 |
| 套装接线修复 | 老物品下次重铸 / 强化 / 重新锻造时会补上套装行；已经集齐但 Lore 没显示的，重铸任意一条即刷新 |
| 加热评分连续化 | 只影响以后取坯的那一刀，历史成品分数不变 |
| RESULT 阶段挂机 / 退出 | 以前会把已经打好的成品一起丢掉，现在会把成品塞回背包、也不断连锻链 |
| 缺键告警修复 | 之前 `getConfig()` 带运行时默认值，告警永远不响；现在读盘上原始文件 |

新增配置段：`imprint`（6 个键）。

升级步骤同前：**备份后删掉 `plugins/ForgingMaster/config.yml` 让它重新生成**。不删也能跑（全部有内置默认值），但启动会 warn 一串缺键（这次真的会 warn 了）。

### 8.4 2.8 → 2.9

**等级不会掉，已得经验不会清；改的只是「以后每把给多少、下一级要多少」。**

| 改动 | 影响 |
| --- | --- |
| 经验公式 | 一次锻造 `10+8×品质+分数/10` → `6+5×品质+0.05×分数`（精良 75 分 34 → 20） |
| 升级曲线 | `80+40×Lv` → `120+55×Lv`（10 级门槛 2600 → 3555） |
| 匠人天赋 | 每 5 级 1 点，七项自选；`data.yml` 新增 `talents` 子段，不改老字段 |
| 天赋接入 | 容差 / 命中区 / 降温 / 叠钢 / 开刃 / 额外词条 / 经验，全部叠在既有公式上 |

新增配置段：`progression`（6 个键）、`talent`（2 个键）。

升级步骤同前。**想让老玩家按新曲线立刻对齐**，删 config.yml 重新生成即可；不删也能跑，
只是启动会 warn 缺这 8 个键（用的是代码内置的同款默认值）。

版本号 2.8.0 → 2.9.0，产物名 `ForgingMaster-2.9.0.jar`。

### 8.5 2.9 → 2.9.1（临摹解锁修复）

**纯 bug 修复，不改任何数值和存档结构。**

以前临摹一旦开上，只有「把那一炉从头搓完」才算结束。中途放弃、关界面、炉子冷了、掉线，
临摹记录都还挂在 `copying` 表里，`begin()` 接着拒绝一切别的剑胚 ——
玩家实际上被锁死在一本谱上，想锻别的只能先把那炉搓完。

| 路径 | 修复前 | 修复后 |
| --- | --- | --- |
| 点 18 放弃锻造 | 锁还挂着 | 解除，并提示「临摹已取消，剑胚锁定解除」 |
| 直接关界面 | 锁还挂着 | 解除 |
| 炉子冷了 / 挂机超时 | 锁还挂着 | 解除 |
| 玩家掉线 | 锁还挂着 | 解除 |
| 正常打完 | settle 里已清 | 不变 |

另外两处体验改进：

- `/zhujian copy` 不带参数时，**先显示当前正在临摹哪本谱、锁的是哪个剑胚**，再显示用法。
  以前只有一行用法，玩家不知道自己是「没在临摹」还是「锁着一本」。
- 被拦住时的提示补上了下一步：`想锻别的剑胚，先 /zhujian copy stop 取消临摹`。
  以前只说「只能用 X 剑胚」，等于告诉玩家「你被锁了」却不给钥匙。

`copy stop` 这个命令一直都在（`/zhujian copy stop`），只是没人知道 —— 所以顺手在
`/zhujian copy` 的状态显示里把它摆出来了。

版本号 2.9.0 → 2.9.1。

### 8.6 2.9.1 → 2.10（双孔分离 + 护甲重修）

这一版有三件事，彼此独立。

#### 一、宝石孔与附魔孔分家

以前宝石和附魔抢同一组孔位（`gems.size() + enchants.size() <= sockets`），
镶了宝石就镶不了附魔。现在两套孔各算各的。

| 项目 | 以前 | 现在 |
| --- | --- | --- |
| 孔位数据 | `sockets` 一个键 | `sockets`（宝石）+ `enchant_sockets`（附魔） |
| 容量判定 | 两者相加 | `gems <= 宝石孔`、`enchants <= 附魔孔` |
| 开孔 | `/zhujian gem socket` | 宝石 `/zhujian gem socket`、附魔 `/zhujian gem esocket` |
| 镶嵌 | `/zhujian gem inlay`、`/zhujian enchant` | 不变，只是各查各的池子 |
| Lore | `◆ 镶嵌孔 [2/3]` | `◆ 镶嵌孔 [宝石 2/2 · 附魔 0/1]` |
| 宝石台 | 5 个按钮 | 7 个：开孔一对、镶嵌一对，左右并列 |

配置新增两个段：`gems.enchant-sockets.tiers`（附魔孔上限，默认和宝石同阶梯）、
`gems.enchant-socket`（附魔开孔费用，默认 8 本书 + 800 币/级）。

**老物品不会被砍孔。** `enchant_sockets` 缺失时回退成宝石孔数，
2.10 之前的东西升级后孔位数不变。新锻出来的物品创建时就写 0，所以是真正独立的。
另外开宝石孔之前会先把回退值「冻结」成实值，否则每开一个宝石孔就会白送一个附魔孔。

#### 二、护甲数值提到原版量级

以前 `armor.tiers` 里是**单件** 0.35 这种量级，铁甲一整套只有 1.4 点护甲——
原版铁套是 15，等于穿了一堆纸。

现在 `armor.tiers` 的含义改成**整套总量**，再按部位拆：

| 档位 | 整套护甲 | 参考 |
| --- | --- | --- |
| 铁 | 15 | 对齐原版铁套 15 |
| 金 | 11 | 对齐原版金套 11 |
| 铜 | 12 | 介于皮革（7）与铁（15）之间 |
| 钻石 | 20 | 对齐原版钻套 20 |
| 下界合金 | 20 | 原版同为 20，韧性更高 |
| 星陨 | 24 | 自定义档，压过下界合金 |

部位占比走新配置 `armor.slot-factor`，默认照原版比例：
头盔 15% / 胸甲 40% / 护腿 30% / 靴子 15%。
以前四个部位拿同一个数，胸甲和靴子一样厚，这次一并修掉。

最终数值 = 整套总量 × 部位占比 × 品质倍率 × (1 + 强化加成)。
品质 COMMON（0.80）下约为原版八折，FINE 起还原并逐步超过。

**老装备会自动补齐。** `StrengthenService.rebalanceArmor()` 在玩家登录 / 重生 /
点背包时扫四个装备槽，把还冻着旧快照的装备按新配置重算一次，**只升不降**，
处理过就打 `armor_rebalance` 标记不再重复。

#### 三、穿两件脱一件护甲清空（老 bug）

四件装备的护甲 modifier **共用同一个键 `fm_armor`**。原版属性表按**键**去重：

```
穿上头盔  → ARMOR 属性挂上 fm_armor = +2
穿上胸甲  → ARMOR 属性再挂 fm_armor = +5   ← 同键，互相顶
脱掉胸甲  → 引擎按键移除 fm_armor         ← 头盔那条一起没了
结果：护甲归零
```

现在键名带部位：`fm_armor_helmet` / `fm_armor_chestplate` / `fm_armor_leggings` /
`fm_armor_boots`，韧性同理。四件各挂各的，互不影响。

- 新物品直接写新键
- 老物品的 `fm_armor` 在 `rebalanceArmor()` 里一次性换成按部位的键
- `Reforge` 里「基础属性键不能被词条覆盖」的判定改成前缀匹配（`Attrs.isBaseKey`），
  否则新的 `fm_armor_chestplate` 会被当成词条键，重铸一次就把基础护甲洗掉

#### 四、粒子疯狂刷异常

```
IllegalArgumentException: missing required data class java.lang.Float
  at CraftParticle.createParticleParam(...)
  at SpiritManager.onHit(SpiritManager.java:267)
```

`SpiritManager.onHit` 和 `GemService` 的合成特效都在用**不带数据**的七参
`spawnParticle`。1.20.5 之后粒子分成两类，`DRAGON_BREATH` 这类必须带 `Float`，
用不带数据的重载每发一次就抛一次异常——战斗里每帧刷屏，
而且异常会把同一个监听器后面的逻辑一起打断。

新增 `com.forgemaster.util.Particles.spawn()`，按 `getDataType()` 分流：
`Void` 走原重载，`Float` 补一个 `0.0f`，其它需要复杂数据的（`DUST` / `BLOCK` / `ITEM`）
直接跳过。副作用是特效偶尔少一簇，比控制台刷屏强。

顺带：`/zhujian give` 现在认 `armor-<剑胚>-<部位>` 形式的装备 id
（例如 `armor-iron-chestplate`），管理员可以直接发装备，不用走完整锻造流程。

#### 五、附魔台 / 铁砧：只封插件物品（2.10.2 修正）

2.10 之前的实现是**把整个附魔台和铁砧封死** —— 右键不让点、界面不让开、
附魔选项不让生成、铁砧结果永远是空。等于顺手把原版附魔和修理一起废了。

服主要的是「插件装备武器禁止交互」，不是「服里不许有附魔台」。现在改成按物品判定：

| 物品 | 附魔台 | 铁砧 |
| --- | --- | --- |
| 原版钻石剑 / 铁胸甲 / 书 | 正常用 | 正常用 |
| `/zhujian` 锻造出来的装备武器 | 拦住 | 拦住 |

判定依据是物品 PDC 上的 `forged` 标记（`ItemFactory.isForged`），跟材质和名字无关。

拦截点从「方块」下移到「槽位」：

| 入口 | 处理 |
| --- | --- |
| 光标拿着锻造品点输入位 | 取消 |
| 从背包 shift 点击锻造品 | 取消 |
| 数字键 / 副手交换进来 | 取消 |
| 鼠标拖拽多个槽 | 取消 |
| 铁砧 `PrepareAnvilEvent` | 输入含锻造品 → 结果置空 |
| 附魔台 `PrepareItemEnchantEvent` | 锻造品 → 不生成附魔选项 |
| 附魔台 `EnchantItemEvent` | 锻造品 → 取消并提示 |

**往里放拦死，往外拿放行。** shift 点击输入位、空光标点输入位都属于取出，
不拦 —— 否则万一锻造品已经在里面（插件重载前放进去的），玩家会拿不出来卡死。

配置新增 `vanilla-guard.block-all`（默认 `false`）：

```yaml
vanilla-guard:
  block-all: false          # false = 只拦插件物品；true = 退回旧的整台封死
  enchanting-table: true
  anvil: true
  grindstone: false
```

`block-all: true` 时连原版物品也拦、方块右键直接不让开，供确实不想要原版附魔的服使用。

`block-events` 这个配置项删掉了 —— 现在没有「拦不拦事件」这一说，
按物品判定是必须做的，留着开关只会让人关掉之后发现锻造品又能附魔了。

版本号 2.10.1 → 2.10.2，自检 274 项。
